## Q1. Node 为什么适合高并发？

**直接回答：**

> 单线程 + 事件循环 + 非阻塞 I/O，少量线程处理大量连接；I/O 等待时不阻塞，靠回调/Promise 继续处理。CPU 密集任务会阻塞，需要 Worker/子进程/拆分服务。

**追问 1：单线程怎么处理并发？**

> 不是同时执行 JS，而是把 I/O 交给 libuv/线程池，完成后回调；主线程只做计算和调度。

**追问 2：什么场景不适合 Node？**

> 大量 CPU 计算（视频转码、复杂加密）、需要多核并行的任务；可以用 Worker/微服务拆分。

**陷阱/加分：**

- Node 不是“多线程 JS”。
- 阻塞主线程会导致所有请求变慢。

## Q2. CommonJS 和 ESM 的区别？

**直接回答：**

> CJS 运行时同步加载，require/module.exports，导出值拷贝；ESM 编译时静态分析，import/export，异步加载，实时绑定，支持 tree shaking 和顶层 await。

**追问 1：Node 怎么用 ESM？**

> package.json `"type": "module"`，或用 `.mjs`；`__dirname` 需要 `import.meta.url` 转换。

**追问 2：循环依赖怎么表现？**

> CJS 返回未完成的对象，可能拿到 undefined；ESM 有暂时性死区，可能报错。

**陷阱/加分：**

- ESM 顶层 this 是 undefined。
- CJS 的 `require` 可以动态条件加载，ESM 需要动态 import。

## Q3. Express 中间件是什么？

**直接回答：**

> 函数 `(req, res, next)`，按注册顺序执行；可以修改 req/res、结束响应或调用 next；错误处理中间件有四个参数 `(err, req, res, next)`。

**追问 1：中间件顺序为什么重要？**

> `express.json()` 要在读 body 前，鉴权要在路由前，错误处理要最后；顺序错了拿不到数据/错误接不住。

**追问 2：怎么捕获异步错误？**

> async 路由里 try/catch + next(err)，或用 asyncHandler 包装 Promise.catch(next)。

**陷阱/加分：**

- 忘了 next 会挂起请求。
- 错误中间件必须四个参数。

## Q4. REST API 怎么设计？

**直接回答：**

> 用资源名 + HTTP 方法，GET 查询、POST 创建、PUT/PATCH 更新、DELETE 删除；用状态码表达结果；统一响应结构；分页/过滤/排序用 query。

**追问 1：PUT 和 PATCH 的区别？**

> PUT 全量更新/替换，PATCH 部分更新；按业务语义选。

**追问 2：分页怎么做？**

> `page/pageSize` 或 `cursor`；返回 total/hasMore；深分页用游标。

**陷阱/加分：**

- 不要把动作塞进 URL（如 /getUser）。
- 状态码不要全用 200。

## Q5. JWT 怎么工作？

**直接回答：**

> 服务端用密钥签名 header.payload.signature，客户端携带 token；服务端验签并解析用户信息。payload 只是 Base64，不是加密；要设置过期，敏感信息不放 payload。

**追问 1：JWT 怎么失效？**

> 短过期 + refresh token；黑名单/版本号；服务端 session 才能立即失效。

**追问 2：token 放哪？**

> Web 端优先 HttpOnly Cookie + CSRF 防护；localStorage 方便但怕 XSS。

**陷阱/加分：**

- JWT 防篡改，不防泄露。
- 不要在 payload 放密码/密钥。

---

## Q6. JWT 和 Session 怎么选？

**直接回答：**

> JWT 无状态、易扩展，但难主动失效；Session 服务端可立即失效，但要共享存储。Web 端常用 HttpOnly Cookie + Session/短 JWT + refresh token。

**追问 1：分布式下 Session 怎么共享？**

> Redis/数据库存 session；或网关粘性会话（不推荐）。

**追问 2：移动端用哪个？**

> 移动端常用 token（JWT/不透明 token），配合刷新/撤销机制；关键是存储安全和过期策略。

**陷阱/加分：**

- “无状态”不等于“更安全”。
- 要结合业务/端/风控选。

---

## Q7. 密码怎么存？

**直接回答：**

> 用 bcrypt/argon2/scrypt + 随机盐，不要明文/MD5/SHA1；HTTPS 传输；登录限流/验证码。

**追问 1：为什么不用 MD5？**

> 太快、可彩虹表/暴力破解；慢哈希 + 盐增加成本。

**追问 2：盐要存吗？**

> 要，和 hash 一起存；每个用户独立随机盐。

**陷阱/加分：**

- 不要自己发明加密算法。
- 密码重置 token 也要安全存储/过期。

## Q8. 怎么防 SQL 注入？

**直接回答：**

> 参数化查询/预编译、ORM、输入校验、最小权限；不要拼接 SQL 字符串。

**追问 1：ORM 就一定安全吗？**

> 不一定，raw SQL/字符串拼接仍可能注入；要看具体用法。

**追问 2：前端校验够吗？**

> 不够，前端可绕过；后端必须校验/参数化。

**陷阱/加分：**

- 错误信息不要泄露 SQL/表结构。
- 日志不要打印敏感数据。

## Q9. 事务是什么？

**直接回答：**

> 一组操作要么全成功要么全失败；ACID；注意隔离级别、死锁、长事务。

**追问 1：转账怎么保证一致性？**

> 事务里扣款+加款，失败回滚；高并发注意锁顺序/死锁重试。

**追问 2：长事务有什么问题？**

> 锁持有久、undo log 大、阻塞其他事务；尽量短小。

**陷阱/加分：**

- 事务不等于分布式事务。
- 跨服务一致性用 Saga/TCC/消息最终一致。

## Q10. Node 怎么处理 CPU 密集任务？

**直接回答：**

> Worker Threads、child_process、拆分微服务、队列异步处理；不要阻塞主事件循环。

**追问 1：Worker 和 child_process 的区别？**

> Worker 共享进程内存（部分），适合计算；child_process 独立进程，隔离更好、开销更大。

**追问 2：什么任务适合队列？**

> 视频转码、图片处理、报表、邮件；用 BullMQ/RabbitMQ/Kafka 异步。

**陷阱/加分：**

- `cluster` 是多进程负载均衡，不是解决单请求 CPU 密集。
- 计算任务要限制并发。

## Q11. Express 错误怎么统一处理？

**直接回答：**

> 路由里 `next(err)`，最后注册四参数错误中间件；异步用 asyncHandler 包装；区分业务错误/系统错误，生产不泄露堆栈。

**追问 1：怎么区分 400/401/403/500？**

> 自定义 HttpError 带 status；业务错误返回明确 message，系统错误统一 500。

**追问 2：怎么记录错误？**

> 结构化日志 + requestId + 用户 ID；接 Sentry/监控；不要记录密码/token。

**陷阱/加分：**

- 错误中间件要放最后。
- 异步错误不 next 会变成未处理 rejection。

---

## Q12. 怎么防刷/限流？

**直接回答：**

> express-rate-limit/Redis 计数、按 IP/用户/接口限流、验证码、黑名单；分布式用 Redis。

**追问 1：限流算法有哪些？**

> 固定窗口、滑动窗口、令牌桶、漏桶；令牌桶允许突发，漏桶平滑。

**追问 2：被限流返回什么？**

> 429 + Retry-After；前端提示/退避重试。

**陷阱/加分：**

- 只按 IP 限流可能误伤 NAT 用户。
- 登录/短信接口要更严格。

---

## Q13. 文件上传要注意什么？

**直接回答：**

> 大小/MIME/后缀校验、鉴权、防路径穿越、存对象存储、图片压缩、限流、病毒扫描（按需）。

**追问 1：为什么不要存本地磁盘？**

> 多实例/扩容/备份/磁盘满；对象存储更适合。

**追问 2：大文件怎么传？**

> 分片、断点续传、并发控制、合并校验；前端算 hash 做秒传。

**陷阱/加分：**

- 不要信任文件名/后缀。
- 上传目录不要可执行。

## Q14. Node 怎么部署？

**直接回答：**

> PM2/Docker + Nginx 反向代理 + HTTPS；环境变量管理密钥；日志/监控/健康检查；多实例/负载均衡。

**追问 1：PM2 的 cluster 模式是什么？**

> 启动多个进程共享端口，利用多核；不是单进程多线程。

**追问 2：怎么做零停机发布？**

> 滚动/蓝绿/灰度；健康检查通过再切流量；保留回滚版本。

**陷阱/加分：**

- 不要把密钥写进镜像/仓库。
- 要有日志/监控/告警。

## Q15. Node 的事件循环和浏览器一样吗？

**直接回答：**

> 不完全一样。Node 分 timers、poll、check 等阶段，每个阶段之间清空 nextTick 和 Promise 微任务；process.nextTick 优先于 Promise。浏览器是宏任务/微任务 + 渲染。

**追问 1：setImmediate 和 setTimeout(0) 谁先？**

> 顶层不确定，取决于启动耗时；在 I/O 回调里 setImmediate 通常先。

**追问 2：nextTick 和 Promise 谁先？**

> nextTick 先。

**陷阱/加分：**

- 不要用 setImmediate 当“立即执行”。
- 阻塞事件循环会影响所有请求。
