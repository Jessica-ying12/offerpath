# 12 · 调试找错 面试问答分册

> 对应知识文档：[12-调试与找错实战.md](../12-调试与找错实战.md)
>
> 用法：面试官通常不会只问“什么是闭包”，而是给你一段代码问“这里有什么问题”。先自己找，再看直接回答和追问。

---

## Q1. 面试官给你一段有 bug 的代码，你的排查流程是什么？

**直接回答：**

> 我会先稳定复现，确认输入、环境和步骤；然后读完整报错，找到错误类型、信息和调用栈里自己的文件；再在关键位置打印变量/断点，二分缩小范围；检查异步时序、引用/可变性、环境/构建；最后修根因并做回归，补一条防复发的测试或监控。

**追问 1：不能复现怎么办？**

> 先加日志/埋点，确认影响面（用户、机型、版本、地区），看监控和错误平台；必要时灰度/回滚，再慢慢定位。

**追问 2：怎么避免“改到能跑就停”？**

> 找到根因，问自己“为什么会出现”，再补同类场景的测试/规范；不只改表面现象。

**陷阱/加分：**

- 不要一上来就改代码，先复现和读报错。
- 不要用 `try {} catch {}` 吞错。

## Q2. 这段代码为什么输出 3 3 3？

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

**直接回答：**

> `var` 是函数作用域，三个回调共享同一个 `i`；循环结束时 `i = 3`。把 `var` 换成 `let`，每次迭代创建新的块级绑定，就能输出 0 1 2。

**追问 1：不用 let 怎么改？**

> 用 IIFE 把每次的 i 作为参数保存，或者 `setTimeout` 用 `bind(null, i)`。

**追问 2：这题考的是什么？**

> 闭包 + 事件循环 + var/let 的作用域差异。

**陷阱/加分：**

- 这不是 setTimeout 的问题，是变量共享。
- 能顺带说出宏任务/微任务更加分。

## Q3. 为什么这里 `this` 丢了？

```js
const user = {
  name: 'Tom',
  greet() { console.log(this.name); },
};
const greet = user.greet;
greet();
```

**直接回答：**

> 这是默认绑定。`greet()` 是普通函数调用，严格模式/模块里 this 是 undefined，非严格浏览器里是 window，不是 user。用 `user.greet()`、`bind(user)` 或箭头函数包一层解决。

**追问 1：`setTimeout(user.greet, 0)` 呢？**

> 同理，this 丢失；用 `setTimeout(() => user.greet(), 0)` 或 `bind`。

**追问 2：箭头函数能解决吗？**

> 如果 greet 定义成箭头函数，它的 this 取外层，不是 user，反而拿不到 user；要看定义位置。

**陷阱/加分：**

- this 的五条规则和优先级要能背。
- 类组件/React 回调里也常见。

## Q4. 为什么 `results` 是空的？

```js
async function loadAll(ids) {
  const results = [];
  ids.forEach(async (id) => {
    results.push(await fetchItem(id));
  });
  return results;
}
```

**直接回答：**

> `forEach` 不会等待 async 回调，函数在请求完成前就返回了。用 `Promise.all(ids.map(id => fetchItem(id)))`，或者 `for...of` 串行 await。

**追问 1：用 map 就一定能等吗？**

> 不一定，`map` 只是返回 Promise 数组，还要 `await Promise.all`。

**追问 2：怎么保证结果顺序？**

> `Promise.all` 的结果顺序和传入顺序一致；如果要按完成顺序，需要额外记录。

**陷阱/加分：**

- forEach 不能 break，也不能 await。
- 并发请求要考虑限流。

## Q5. 快速搜索时，旧结果覆盖新结果，怎么排查和修复？

**直接回答：**

> 这是请求竞态：请求完成顺序不等于发起顺序。用 AbortController 取消旧请求，或记录请求序号，只渲染最新一次；再加防抖减少请求量。

**追问 1：取消请求后，旧请求还会执行吗？**

> 浏览器会中止 fetch，但服务端可能已经处理；前端只关心不再渲染旧结果。

**追问 2：为什么防抖不能完全解决竞态？**

> 防抖只是减少请求，仍可能有两个请求重叠；取消/序号才是根本。

**陷阱/加分：**

- 搜索、切 tab、翻页都可能竞态。
- 可以在请求层统一封装 latestRequest。

## Q6. 为什么删除列表第一项后，输入框内容串了？

```jsx
{todos.map((todo, index) => (
  <TodoItem key={index} todo={todo} />
))}
```

**直接回答：**

> 用 index 做 key，删除/排序后 React 会错误复用节点和组件状态。key 应该用稳定唯一的业务 id。

**追问 1：key 重复会怎样？**

> React 会警告，复用行为不可预测，状态可能错乱。

**追问 2：key 需要全局唯一吗？**

> 不需要，兄弟节点之间唯一即可。

**陷阱/加分：**

- 随机 key 会导致组件整体重建。
- 列表项有内部 state/输入框时尤其明显。

## Q7. 为什么 useEffect 里的 `count` 一直是 0？

```jsx
useEffect(() => {
  const timer = setInterval(() => setCount(count + 1), 1000);
  return () => clearInterval(timer);
}, []);
```

**直接回答：**

> 空依赖让 effect 只执行一次，闭包捕获了首次渲染的 count=0。用函数式更新 `setCount(c => c + 1)`，或者把 count 放进依赖（会重建定时器）。

**追问 1：为什么函数式更新能拿到最新值？**

> React 把更新函数排进队列，执行时传入上一次的 state，不依赖闭包里的旧值。

**追问 2：还有哪些闭包陷阱？**

> 事件监听、WebSocket 回调、debounce/throttle 里读取 state，都可能读到旧值。

**陷阱/加分：**

- 补依赖不是唯一解，要看是否需要重建副作用。
- 可以用 useRef 保存最新值。

## Q8. 组件卸载后还报 setState，怎么修？

```jsx
useEffect(() => {
  const timer = setInterval(() => setCount(c => c + 1), 1000);
}, []);
```

**直接回答：**

> 定时器在组件卸载后还在跑，继续 setState。要在 effect 的清理函数里 `clearInterval`；异步请求还要用 cancelled 标志或 AbortController。

**追问 1：为什么 React 会警告？**

> 组件已经卸载，State 不再属于任何组件；虽然新版本不再警告，但仍然是内存泄漏。

**追问 2：怎么发现这类泄漏？**

> 在控制台看警告、用 Heap Snapshot 对比、检查定时器/监听器/订阅是否清理。

**陷阱/加分：**

- 事件监听、WebSocket、轮询都要清理。
- 清理函数在依赖变化前也会执行。

## Q9. 为什么 RN 长列表很卡？

```jsx
<ScrollView>
  {posts.map(post => <PostCard key={post.id} post={post} />)}
</ScrollView>
```

**直接回答：**

> ScrollView 会一次性渲染所有子项，1000 条就创建 1000 个原生视图。换成 FlatList，只渲染可视区域附近的项，并加 `keyExtractor`、`initialNumToRender`、`windowSize`，列表项用 memo。

**追问 1：固定行高怎么优化？**

> 加 `getItemLayout`，跳过测量；行高不固定就不要用。

**追问 2：`removeClippedSubviews` 有什么坑？**

> 复杂 item/动画可能被错误裁剪，Android 上要测。

**陷阱/加分：**

- FlatList 不要嵌套在 ScrollView 里。
- 图片要指定尺寸、压缩。

## Q10. 小程序 `setData` 后列表变成数字了，为什么？

```js
this.setData({
  list: this.data.list.push(item),
});
```

**直接回答：**

> `push` 返回的是新长度（number），`list` 被设置成数字，WXML 无法遍历。用 `[...this.data.list, item]` 或路径更新。

**追问 1：为什么不能直接改 `this.data.list`？**

> 直接改不会触发视图更新，还可能数据不一致；要用 setData 传新数组/路径。

**追问 2：大列表怎么优化？**

> 分页、路径更新、只传变化字段、虚拟列表。

**陷阱/加分：**

- `setData` 数据量有上限。
- 不要在 `onPageScroll` 里频繁 setData。

## Q11. 接口报 CORS，是前端代码的 bug 吗？

**直接回答：**

> 不是 JS 语法错误，是浏览器同源策略。服务端没返回允许跨域的响应头，或者开发环境没配代理。解决：后端 CORS、开发代理、同域部署/Nginx 反向代理。

**追问 1：为什么 Postman/curl 能通？**

> CORS 是浏览器行为，Postman 不受同源策略限制。

**追问 2：带 cookie 的跨域怎么配？**

> `credentials: 'include'`，服务端 `Allow-Credentials: true`，`Allow-Origin` 不能是 `*`。

**陷阱/加分：**

- 预检 OPTIONS 失败也会报 CORS。
- 代理是开发方案，生产要配网关。

## Q12. 为什么 `z-index: 9999` 还是被盖住？

**直接回答：**

> 父元素可能创建了新的层叠上下文（`transform`、`opacity < 1`、`filter` 等），子元素的 z-index 只在父级内部比较，跳不出去。把浮层挂到 body/Portal，或移除父级的这些属性。

**追问 1：哪些属性会创建层叠上下文？**

> 定位 + z-index、fixed/sticky、opacity < 1、transform/filter、isolation、flex/grid 子项且 z-index 不为 auto 等。

**追问 2：怎么快速确认？**

> DevTools 看 Layers/Computed，或逐层移除 transform/opacity 试。

**陷阱/加分：**

- z-index 只对定位元素/flex/grid 子项生效。
- 不要用更大的 z-index 硬压。

## Q13. 为什么 Flex 子项的省略号不生效？

```css
.text {
  flex: 1;
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

**直接回答：**

> Flex 子项默认 `min-width: auto`，内容会把宽度撑开，`overflow: hidden` 没有空间。加 `min-width: 0` 就能收缩并显示省略号。

**追问 1：多行省略怎么写？**

> `display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: 2; overflow: hidden;`。

**追问 2：为什么行内元素不行？**

> `text-overflow` 需要块级/可设宽高的容器；行内元素没有宽度约束。

**陷阱/加分：**

- 图片/长单词也会撑破 Flex。
- 省略号三件套要一起写。

## Q14. 怎么排查内存泄漏？

**直接回答：**

> 先看内存曲线是否持续上升；用 Chrome DevTools Memory → Heap Snapshot 对比操作前后的快照，找 Detached DOM、异常增长的对象；再检查定时器、事件监听、闭包、全局变量、Map 缓存。

**追问 1：SPA 切页面内存不降，可能是哪里？**

> 页面组件卸载没清理定时器/监听/订阅，或者全局 store/缓存一直持有数据。

**追问 2：怎么预防？**

> 统一封装订阅/定时器，组件卸载时清理；Code Review 加检查项；线上监控内存。

**陷阱/加分：**

- 内存不下降不一定是泄漏，可能是 GC 还没跑。
- WeakMap/WeakSet 可以避免强引用。

---

## Q15. 线上白屏怎么排查？

**直接回答：**

> 先分三类：JS 异常、bundle/资源加载失败、原生/服务端问题。看错误监控、Network、CDN、发布记录；先止血（回滚/降级/开关），再定位根因，最后补监控/测试防复发。

**追问 1：只有部分用户白屏？**

> 看机型/版本/地区/网络；可能是兼容性、缓存、CDN 节点、灰度版本问题。

**追问 2：怎么防白屏？**

> 错误边界、骨架/兜底页、资源加载重试、灰度发布、sourcemap 还原堆栈。

**陷阱/加分：**

- 白屏不一定是前端 JS，可能是 HTML/资源 404。
- 先止血再根治，别在生产上边查边改。

---

## Q16. 怎么避免同类 bug 再发生？

**直接回答：**

> 修根因 + 补测试/监控 + 沉淀规范。比如闭包问题补 lint 规则/Code Review 检查项；列表 key 问题写进组件规范；请求竞态封装成统一工具。

**追问 1：没有测试团队怎么做？**

> 至少写关键路径的单测/手测清单；用错误监控/埋点兜底。

**追问 2：怎么推动团队？**

> 先做小范围试点，用数据证明收益；把检查项放进 CI/模板，降低执行成本。

**陷阱/加分：**

- 不要只写“下次注意”。
- 规范要工具化，不能只靠记忆。
