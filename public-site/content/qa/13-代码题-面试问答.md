## Q1. 现场写代码，你怎么开始？

**直接回答：**

> 我先确认输入/输出、边界、是否需要异步/取消/并发限制；举 2-3 个例子；说暴力解和优化思路；再写代码；最后手动跑例子、分析复杂度、补边界。

**追问 1：如果一时没思路？**

> 先写暴力解，保证正确；再找重复计算/可用的数据结构优化；边写边说出假设，不要沉默。

**追问 2：写错了怎么办？**

> 用例子逐步跑，打印/口述变量变化；不要慌，先定位是哪一步不符合预期。

**陷阱/加分：**

- 先问清楚再写，比写完再改加分。
- 代码要能跑，边界要处理。

## Q2. 实现 `sleep(ms)`

**直接回答：**

> 返回一个 Promise，setTimeout 到点 resolve。

```js
const sleep = (ms) =>
  new Promise((resolve) => setTimeout(resolve, ms));
```

**追问 1：能同步阻塞吗？**

> 不能，JS 没有同步 sleep；同步阻塞会卡住主线程，只能用异步等待。

**追问 2：`sleep(0)` 什么时候执行？**

> 进入宏任务队列，等当前同步代码和微任务执行完。

**陷阱/加分：**

- 负数会被 setTimeout 当作 0。
- 不要用忙等待（while）实现 sleep。

## Q3. 实现带超时的 `fetch`

**直接回答：**

> 用 AbortController，setTimeout 到点 abort；fetch 捕获 AbortError 转成“超时”，finally 清理定时器。

```js
async function fetchWithTimeout(url, options = {}, timeout = 5000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);

  try {
    return await fetch(url, { ...options, signal: controller.signal });
  } catch (err) {
    if (err.name === 'AbortError') throw new Error('请求超时');
    throw err;
  } finally {
    clearTimeout(timer);
  }
}
```

**追问 1：调用方自己传了 signal 怎么办？**

> 要合并两个 signal，或监听外部 signal 去 abort 内部 controller；现代浏览器可以用 `AbortSignal.any`。

**追问 2：超时后服务端还会执行吗？**

> 可能，前端只是不再等；重要操作要后端幂等/超时取消。

**陷阱/加分：**

- 一定要 clearTimeout，避免定时器泄漏。
- 区分“超时”和“用户主动取消”。

## Q4. 实现 `retry(fn, times, delay)`

**直接回答：**

> 循环调用 fn，成功就返回；失败记录错误，没到次数就等一会儿再试；支持指数退避和抖动；最后抛出最后一次错误。

```js
async function retry(fn, { times = 3, delay = 500 } = {}) {
  let lastError;

  for (let attempt = 1; attempt <= times; attempt++) {
    try {
      return await fn(attempt);
    } catch (err) {
      lastError = err;
      if (attempt === times) break;
      await new Promise((r) => setTimeout(r, delay * attempt));
    }
  }

  throw lastError;
}
```

**追问 1：所有错误都该重试吗？**

> 不是。网络错误/5xx 可以重试；400/401/403 这类不可重试；支付/下单要幂等。

**追问 2：为什么要抖动？**

> 多个客户端同时重试会造成雪崩；加随机抖动打散。

**陷阱/加分：**

- 要有最大次数/总超时。
- 重试要保留最后一次错误。

## Q5. 实现并发限制 `runWithLimit(tasks, limit)`

**直接回答：**

> 维护一个 nextIndex，启动 limit 个 worker，每个 worker 不断取下一个任务执行，结果按原下标存；最后 Promise.all 等待所有 worker。

```js
async function runWithLimit(tasks, limit = 3) {
  const results = new Array(tasks.length);
  let nextIndex = 0;

  async function worker() {
    while (nextIndex < tasks.length) {
      const index = nextIndex++;
      results[index] = await tasks[index]();
    }
  }

  await Promise.all(
    Array.from({ length: Math.min(limit, tasks.length) }, () => worker())
  );

  return results;
}
```

**追问 1：怎么保证结果顺序？**

> 用任务原下标写入 results，不按完成顺序 push。

**追问 2：某个任务失败怎么办？**

> 当前实现会让 Promise.all reject；要等全部结束用 allSettled，或每个任务 try/catch 记录失败后继续。

**陷阱/加分：**

- limit 要处理 0/负数。
- 空数组直接返回 [].

## Q6. 串行和并行怎么实现？怎么选？

**直接回答：**

> 串行用 for...of + await，一个完成再下一个；并行用 Promise.all(tasks.map(fn))。有依赖用串行，互不依赖用并行，量大用并发限制。

```js
async function sequential(tasks) {
  const results = [];
  for (const task of tasks) results.push(await task());
  return results;
}

async function parallel(tasks) {
  return Promise.all(tasks.map((task) => task()));
}
```

**追问 1：Promise.all 的结果顺序是完成顺序吗？**

> 不是，和传入顺序一致。

**追问 2：并行请求太多会怎样？**

> 压垮服务/浏览器连接数限制/内存上升；用并发池限流。

**陷阱/加分：**

- 串行总耗时是相加，并行是最慢的那个。
- 错误处理策略要提前定。

## Q7. 只保留最新一次请求，怎么实现？

**直接回答：**

> 每次请求前 abort 上一个 controller，或者记录请求序号，回来时只处理最新序号。搜索场景再配防抖。

```js
function createLatestRequest() {
  let controller = null;

  return async function run(requestFn) {
    if (controller) controller.abort();
    controller = new AbortController();

    try {
      return await requestFn(controller.signal);
    } catch (err) {
      if (err.name === 'AbortError') return null;
      throw err;
    }
  };
}
```

**追问 1：为什么防抖不够？**

> 防抖只减少请求，仍可能重叠；取消/序号才能保证旧结果不覆盖新结果。

**追问 2：旧请求返回 null 怎么处理？**

> 调用方判断 null 不渲染；或者用序号方案，直接 return。

**陷阱/加分：**

- 切页面/切 tab 也要取消。
- 取消后不要当错误提示。

## Q8. 异步缓存：相同参数只请求一次

**直接回答：**

> 用 Map 缓存 Promise，而不是缓存结果；并发调用同一个 key 时返回同一个 Promise；失败时删除缓存，允许重试。

```js
function asyncMemoize(fn) {
  const cache = new Map();

  return function memoized(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);

    const promise = Promise.resolve()
      .then(() => fn.apply(this, args))
      .catch((err) => {
        cache.delete(key);
        throw err;
      });

    cache.set(key, promise);
    return promise;
  };
}
```

**追问 1：为什么缓存 Promise 而不是结果？**

> 并发请求还没结果时，缓存结果没有东西可存；缓存 Promise 可以共享同一个进行中的请求。

**追问 2：key 怎么设计？**

> 参数稳定序列化；对象要排序 key，或自己生成业务 key；函数/undefined 不适合 JSON.stringify。

**陷阱/加分：**

- 缓存要有过期/清理，避免内存增长。
- 失败不缓存，否则一次失败永久失败。

## Q9. 手写 `Promise.all`

**直接回答：**

> 返回新 Promise，遍历所有项，用 Promise.resolve 包一层；每个成功写入对应下标，计数到长度就 resolve；任何一个 reject 就 reject；空数组直接 resolve([])。

```js
function promiseAll(list) {
  return new Promise((resolve, reject) => {
    const items = Array.from(list);
    const results = new Array(items.length);
    let count = 0;

    if (items.length === 0) return resolve(results);

    items.forEach((item, index) => {
      Promise.resolve(item).then(
        (value) => {
          results[index] = value;
          count++;
          if (count === items.length) resolve(results);
        },
        reject
      );
    });
  });
}
```

**追问 1：为什么用 Promise.resolve 包一层？**

> 兼容普通值/thenable，统一用 then 处理。

**追问 2：结果顺序怎么保证？**

> 按 index 写入，不按完成顺序。

**陷阱/加分：**

- 空数组要立即 resolve。
- 任何一个失败立即 reject。

## Q10. 深拷贝怎么写？

**直接回答：**

> 递归复制，原始类型直接返回；处理 Date/RegExp/Map/Set；用 WeakMap 处理循环引用；数组保持数组，普通对象保持原型。

```js
function deepClone(value, cache = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (cache.has(value)) return cache.get(value);

  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);

  const cloned = Array.isArray(value)
    ? []
    : Object.create(Object.getPrototypeOf(value));

  cache.set(value, cloned);

  for (const key of Reflect.ownKeys(value)) {
    cloned[key] = deepClone(value[key], cache);
  }

  return cloned;
}
```

**追问 1：Map/Set 怎么处理？**

> 单独判断，创建新 Map/Set，递归 clone 键和值；否则会被当成普通对象。

**追问 2：JSON 方法有什么问题？**

> 丢函数/undefined/Symbol，Date 变字符串，循环引用报错，Map/Set 变空对象。

**陷阱/加分：**

- 函数通常按引用返回。
- 循环引用必须用 WeakMap。

## Q11. 实现 `groupBy` 和数组扁平化

**直接回答：**

> groupBy 用 reduce 累加，按 key 分组；扁平化用 reduce + 递归，控制 depth。

```js
function groupBy(list, getKey) {
  return list.reduce((acc, item) => {
    const key = typeof getKey === 'function' ? getKey(item) : item[getKey];
    (acc[key] ||= []).push(item);
    return acc;
  }, {});
}

function flatten(arr, depth = Infinity) {
  return arr.reduce((acc, item) => {
    if (Array.isArray(item) && depth > 0) {
      acc.push(...flatten(item, depth - 1));
    } else {
      acc.push(item);
    }
    return acc;
  }, []);
}
```

**追问 1：groupBy 的 key 是对象怎么办？**

> 对象不能直接做对象 key，会变成 `[object Object]`；要用 Map，或序列化成字符串。

**追问 2：扁平化递归太深怎么办？**

> 用迭代 + 栈，避免栈溢出。

**陷阱/加分：**

- depth=0 要返回浅拷贝。
- 不要修改原数组。

## Q12. 防抖和节流怎么写？

**直接回答：**

> 防抖用 clearTimeout + setTimeout，停止触发 delay 后执行；节流用时间戳/定时器，固定时间最多一次。要保留 this/参数，提供 cancel。

```js
function debounce(fn, delay = 300) {
  let timer = null;

  function debounced(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      fn.apply(this, args);
    }, delay);
  }

  debounced.cancel = () => {
    if (timer) clearTimeout(timer);
    timer = null;
  };

  return debounced;
}
```

**追问 1：节流怎么保证最后一次执行？**

> 时间戳 + 定时器结合，尾部补一次；记录最后一次参数。

**追问 2：什么时候用哪个？**

> 搜索输入/resize 用防抖；滚动/拖拽/按钮点击用节流。

**陷阱/加分：**

- 组件卸载要 cancel。
- 防抖/节流不是“减少函数执行”这么简单，要保留上下文。

## Q13. 实现发布订阅 `EventEmitter`

**直接回答：**

> 用 Map 存事件名到回调数组；on 注册、off 删除、emit 遍历执行、once 包一层执行后删除；emit 时复制数组，避免遍历中修改。

```js
class EventEmitter {
  constructor() { this.events = new Map(); }

  on(type, fn) {
    if (!this.events.has(type)) this.events.set(type, []);
    this.events.get(type).push(fn);
    return () => this.off(type, fn);
  }

  off(type, fn) {
    const list = this.events.get(type);
    if (!list) return;
    const i = list.indexOf(fn);
    if (i > -1) list.splice(i, 1);
  }

  once(type, fn) {
    const wrapper = (...args) => {
      this.off(type, wrapper);
      fn(...args);
    };
    this.on(type, wrapper);
  }

  emit(type, ...args) {
    const list = this.events.get(type);
    if (!list) return false;
    [...list].forEach((fn) => fn(...args));
    return true;
  }
}
```

**追问 1：为什么 emit 要复制数组？**

> 回调里可能 off/on，直接遍历原数组会漏执行/死循环。

**追问 2：怎么避免内存泄漏？**

> 组件卸载时 off；返回取消订阅函数；弱引用/生命周期管理。

**陷阱/加分：**

- 错误隔离：一个回调抛错不应影响其他回调（按需求）。
- once 的 wrapper 要能被 off。

## Q14. 实现 LRU 缓存

**直接回答：**

> 哈希表 + 双向链表，Map 版最简单：get 后 delete+set 移到末尾，put 超容量删除第一个 key。

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map();
  }

  get(key) {
    if (!this.map.has(key)) return -1;
    const value = this.map.get(key);
    this.map.delete(key);
    this.map.set(key, value);
    return value;
  }

  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.capacity) {
      const oldest = this.map.keys().next().value;
      this.map.delete(oldest);
    }
  }
}
```

**追问 1：为什么不用数组？**

> 数组移动 O(n)，无法 O(1) 调整顺序。

**追问 2：并发场景要注意什么？**

> 加锁/原子操作；多线程下 Map 不是线程安全的。

**陷阱/加分：**

- capacity 为 0 要处理。
- get 也算“使用”，要移到最近。

## Q15. React `useDebounce` 和 `useFetch` 怎么写？

**直接回答：**

> useDebounce 用 useEffect + setTimeout，返回延迟后的值；useFetch 用 useEffect + AbortController，返回 data/loading/error，依赖 URL 变化时取消旧请求。

```jsx
function useDebouncedValue(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);

  return debounced;
}
```

**追问 1：useFetch 为什么不能直接在组件里 fetch？**

> 每次渲染都可能重复请求；要放 useEffect，并管理 loading/error/取消。

**追问 2：useFetch 的依赖是什么？**

> URL；如果依赖对象/函数，要稳定引用。

**陷阱/加分：**

- 卸载后不要 setState。
- 请求竞态用 AbortController/active 标志。

## Q16. RN 分页和防止重复请求怎么写？

**直接回答：**

> 用 useRef 保存 page 和 loading 标志，load 时先判断 loadingRef；成功后追加数据，根据返回条数判断 hasMore；FlatList 的 onEndReached 调 loadMore，onRefresh 重置到第一页。

```jsx
const loadingRef = useRef(false);
const pageRef = useRef(1);

const load = useCallback(async (page, replace = false) => {
  if (loadingRef.current) return;
  loadingRef.current = true;

  try {
    const res = await fetch(`${API}?_page=${page}&_limit=10`);
    const data = await res.json();
    setItems((prev) => (replace ? data : [...prev, ...data]));
    setHasMore(data.length === 10);
    pageRef.current = page;
  } finally {
    loadingRef.current = false;
  }
}, []);
```

**追问 1：为什么用 ref 而不是 state 做 loading 锁？**

> state 更新是异步的，onEndReached 连续触发时可能拿到旧值；ref 同步更新，适合做锁。

**追问 2：怎么判断没有更多？**

> 返回条数小于 pageSize，或后端返回 hasMore。

**陷阱/加分：**

- 分页要处理空页/错误/重试。
- FlatList 要 keyExtractor。

## Q17. 写完代码怎么自测？

**直接回答：**

> 至少跑四类：正常输入、空输入、边界（单元素/重复/超大）、错误（null/类型不对/网络失败）；再检查是否修改入参、复杂度、并发/取消/顺序。

**追问 1：没有测试框架怎么办？**

> 用 console/断言函数写最小用例，或手动在控制台跑；关键函数补单测。

**追问 2：怎么分析复杂度？**

> 看循环层数、递归深度、额外空间；能说出最好/最坏/平均。

**陷阱/加分：**

- 不要只测 happy path。
- 面试时口述测试用例也是加分项。
