# 09 · 面试题库与回答话术

> 适用岗位：移动前端工程师（React / React Native / 小程序 / Flutter 加分）
>
> 用法：
> 1. 先看第 1-6 节，把自我介绍和项目讲述练熟。
> 2. 再用第 5-13.6 节刷技术题，每题按“定义 → 原理 → 场景 → 项目例子”组织。
> 3. 最后看第 14-18 节的追问、不会的题、眼神、HR 和冲刺计划。
> 4. 找错题和现场代码题，分别用 12、13 文档做专项训练。
> 5. 每章对应的“直接回答 + 追问答案”分册见 [面试问答/README.md](面试问答/README.md)。
>
> **重要：项目模板里的 `[项目名]`、`[X]%` 必须替换成你的真实数据。可以优化表达，不能虚构职责和技术细节。**

## 1. 先明确两件事

### 1.1 这个岗位在考察什么

| 考察维度 | 面试官怎么判断 | 你要怎么准备 |
|---|---|---|

| 解决问题能力 | 场景题、线上故障、取舍 | 场景题 + 复盘 |
| 沟通与稳定性 | 表达是否清楚、是否听得懂问题、是否诚实 | 第 10-12 节 |

### 1.2 诚信边界

可以做的：

- 把“参与”说清楚是参与，把“负责”说清楚负责哪部分。
- 用 STAR 把真实经历讲得有条理。
- 把同类经验迁移到 JD 的语言上（比如 H5 内嵌 App 的经验，可以讲 WebView/JSBridge）。
- 不会的题，承认并给出思路。

不可以做的：

- 虚构公司、项目、职责、技术栈。
- 把别人写的代码说成自己独立完成。
- 把“了解”说成“精通”。
- 编造性能数据、用户量、QPS。

**面试官深挖三层就会知道真假：**

```text
第一层：你做了什么？
第二层：具体哪个文件/哪个组件/哪个 API？
第三层：当时遇到什么报错？为什么选这个方案？怎么验证的？
```

如果三层都答不上来，前面包装得再好也会崩。

## 4. 项目讲述：STAR + 细节

### 4.1 STAR 结构

```text
S（Situation）背景：什么业务、什么规模、为什么要做
T（Task）任务：你的目标、你的职责、时间/资源约束
A（Action）行动：你具体做了什么、为什么这么做、遇到什么困难
R（Result）结果：数据、上线效果、复盘
```

再加一个 **R（Reflection）复盘**：如果重做，你会怎么改。这会让面试官觉得你有成长性。

### 4.2 项目讲述的 6 个必答细节

面试官一定会追问：

1. **你具体负责哪部分？** 说清楚模块，不要说“整个项目都是我做的”。
2. **最难的技术点是什么？** 选一个你真的解决过的。
3. **为什么用这个方案？** 对比至少一个替代方案。
4. **怎么验证有效？** 指标、埋点、Profiler、线上数据。
5. **遇到过什么线上问题？** 怎么定位、怎么修复、怎么防复发。
6. **如果重做，你会怎么改？** 体现复盘。

### 4.3 模板 A：RN 列表性能优化

> **S：** `[项目名]` 是一个电商 App，商品列表有 `[1000+]` 条数据，之前用 ScrollView 渲染，滚动明显掉帧，低端安卓机更严重，用户反馈“卡”。
>
> **T：** 我负责列表性能优化，目标是滚动帧率从 `[30]` 提升到 `[50+]`，首屏渲染时间降低 `[30%]`，同时不改变现有交互。
>
> **A：**
> - 先用 React DevTools Profiler 和 RN Performance Monitor 定位，发现两个问题：一次性渲染所有 item；父组件每次 state 变化都导致整列重渲染。
> - 把 ScrollView 换成 FlatList，加上 `keyExtractor`、`getItemLayout`（行高固定）、`initialNumToRender`、`maxToRenderPerBatch`、`windowSize`。
> - 列表项抽成 `memo` 组件，回调用 `useCallback`，避免每次传新函数。
> - 图片改成 CDN 缩略图 + 固定宽高，避免布局抖动。
> - 分页加载，`onEndReached` 每次加载 20 条。
> - 最后用 Hermes 的 Profiler 复测，确认 JS 线程不再有长任务。
>
> **R：** 滚动帧率稳定在 `[55]` 左右，首屏从 `[2.8s]` 降到 `[1.6s]`，相关客诉下降 `[X%]`。我把这套优化整理成了团队 checklist。
>
> **反思：** 如果重做，我会在项目初期就建立性能基线（FPS、首屏、包体积），并接入监控，而不是等用户反馈才优化。

**可能的追问：**

- `getItemLayout` 的原理？→ 跳过测量，直接告诉列表每项的高度和偏移。
- 行高不固定怎么办？→ 不能用 `getItemLayout`，用 `onLayout` 缓存或预估高度，或换 FlashList。
- `removeClippedSubviews` 有什么坑？→ 复杂 item/动画可能被裁剪异常，Android 上要测。
- 为什么 `memo` 没生效？→ props 里有新对象/新函数，或组件内部有自己的 state。

> **S：** 公司要做一个微信小程序商城，包含首页、商品列表、详情、购物车、订单，工期 `[6 周]`，团队 `[X]` 人。

> **T：** 我负责小程序端的整体搭建和核心页面，包括技术选型、目录规范、请求封装、组件库、性能优化和提审上线。

> **A：**
> - 选型：原生小程序，原因是团队没有 Taro 经验，且需要稳定的微信支付/登录能力。

- 为什么不用 Taro/uni-app？→ 团队技术栈、原生能力、包体积、调试成本。

### 高频口语答案

**Q：BFC 是什么？**

> BFC 是块级格式化上下文，是一个独立的布局区域，内部元素不会影响外部。触发方式有 `display: flow-root`、`overflow: hidden`、`float`、`position: absolute/fixed`、`display: flex/grid` 等。它能清除浮动、防止 margin 塌陷、阻止元素被浮动覆盖。项目里我一般用 `display: flow-root`，因为它没有副作用。

**Q：移动端 1px 怎么处理？**

> 高清屏上 1 CSS 像素会被放大成多个物理像素，看起来偏粗。常用做法是用伪元素画一条 1px 的线，然后用 `transform: scaleY(0.5)`（DPR=2）或 `scaleY(0.3333)`（DPR=3）缩放。也有用 `box-shadow` 或 `0.5px` 的，但兼容性不如 transform。

**Q：重排和重绘的区别？**

> 重排是几何属性变化，浏览器要重新计算布局，代价高；重绘是颜色等外观变化，不改变布局。优化方式：批量修改样式、先读后写、用 class 切换、动画用 transform/opacity、图片写宽高、长列表虚拟滚动、避免频繁读取 offsetWidth。

### 高频口语答案

**Q：useEffect 的依赖数组？**

> 不写依赖：每次渲染后都执行；空数组：只在挂载后执行一次；有依赖：挂载后和依赖变化时执行。依赖里用到的 props/state 都应该写进去，否则会读到旧值。清理函数在依赖变化前和卸载时执行，用来清除定时器、取消请求、移除监听。开发环境 StrictMode 会执行两次，这是故意的。

**Q：为什么 key 不能用 index？**

> 列表增删或排序时 index 会变化，React 会错误复用节点，导致组件状态错位、多余渲染，甚至输入框内容串行。key 应该用稳定唯一的业务 id。

**Q：Fiber 解决了什么？**

> React 16 之前，组件树一旦开始渲染就不能中断，大树会长时间占用主线程，导致输入卡顿。Fiber 把渲染拆成小任务，render 阶段可以中断、让出主线程，优先处理高优先级更新，commit 阶段再一次性更新 DOM。配合双缓存和 lanes 优先级模型实现并发渲染。

**Q：useMemo 和 useCallback 的区别？**

> useMemo 缓存计算结果，useCallback 缓存函数引用；`useCallback(fn, deps)` 等价于 `useMemo(() => fn, deps)`。主要用于避免重复计算和配合 React.memo 减少子组件重渲染，不要滥用。

**Q：RN 的新架构解决了什么？**

> 旧架构通过 Bridge 异步通信，数据要序列化成 JSON，批量排队，高频调用容易堵，启动时还要初始化所有原生模块。新架构用 JSI 让 JS 直接调用 C++/原生对象，支持同步；TurboModules 按需加载；Fabric 用 C++ 实现 shadow tree，支持同步布局和并发渲染；Codegen 生成类型安全的胶水代码；Hermes 预编译字节码提升启动。整体上减少了通信开销，启动更快，也更好地支持 React 18 的并发特性。

**Q：RN 动画为什么卡？**

> JS 驱动的动画每帧都要通过桥/JS 线程更新，主线程一忙就掉帧。简单动画用 Animated 并开启 useNativeDriver，让动画跑在 UI 线程；复杂手势/动画用 Reanimated，worklet 跑在 UI 线程；避免在动画过程中 setState。

**Q：setData 为什么慢？怎么优化？**

### 13.3 深拷贝

```js
function deepClone(value, cache = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (cache.has(value)) return cache.get(value);

  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);

  if (value instanceof Map) {
    const map = new Map();
    cache.set(value, map);
    value.forEach((v, k) => map.set(deepClone(k, cache), deepClone(v, cache)));
    return map;
  }

  if (value instanceof Set) {
    const set = new Set();
    cache.set(value, set);
    value.forEach((v) => set.add(deepClone(v, cache)));
    return set;
  }

  const cloned = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  cache.set(value, cloned);

  Reflect.ownKeys(value).forEach((key) => {
    cloned[key] = deepClone(value[key], cache);
  });

  return cloned;
}
```

### 13.4 Promise.all

```js
function promiseAll(list) {
  return new Promise((resolve, reject) => {
    const items = Array.from(list);
    const results = new Array(items.length);
    let count = 0;

    if (items.length === 0) return resolve(results);

    items.forEach((item, index) => {
      Promise.resolve(item).then(
        (value) => {
          results[index] = value;
          count++;
          if (count === items.length) resolve(results);
        },
        reject
      );
    });
  });
}
```

Function.prototype.myCall = function (context, ...args) {
  context = context == null ? globalThis : Object(context);
  const key = Symbol('fn');
  context[key] = this;
  const result = context[key](...args);
  delete context[key];
  return result;
};

Function.prototype.myBind = function (context, ...boundArgs) {
  const fn = this;
  function Bound(...callArgs) {
    return fn.apply(
      this instanceof Bound ? this : context,
      [...boundArgs, ...callArgs]
    );
  }
  Bound.prototype = Object.create(fn.prototype);

### 13.8 发布订阅

```js
class EventEmitter {
  constructor() {
    this.events = new Map();
  }
  on(type, fn) {
    if (!this.events.has(type)) this.events.set(type, []);
    this.events.get(type).push(fn);
    return () => this.off(type, fn);
  }
  off(type, fn) {
    const list = this.events.get(type);
    if (!list) return;
    const i = list.indexOf(fn);
    if (i > -1) list.splice(i, 1);
  }
  emit(type, ...args) {
    const list = this.events.get(type);
    if (!list) return false;
    [...list].forEach((fn) => fn(...args));
    return true;
  }
}
```

| 6 | BuildContext 是什么？ | Element 的接口；查找祖先/Theme/Provider | 为什么 initState 不能用 |
| 7 | Key 有什么用？ | 复用 Element/State；ValueKey/GlobalKey | 列表排序 |

| 9 | 布局约束规则？ | constraints down, sizes up, parent sets position | overflow 怎么解决 |
| 10 | Expanded vs Flexible？ | 强制填满 vs 允许伸缩 | 文本省略 |
| 11 | ListView.builder 优势？ | 按需构建、长列表性能好 | itemExtent 作用 |
| 12 | 状态管理怎么选？ | setState/Provider/Riverpod/Bloc/GetX | 为什么不要过度设计 |
| 13 | Provider 原理？ | InheritedWidget + ChangeNotifier + notifyListeners | Consumer 和 watch 区别 |
| 14 | FutureBuilder 怎么用？ | loading/error/data 三态；Future 放 State | 为什么不能每次 build 新建 Future |
| 15 | Future vs Stream？ | 一次结果 vs 连续事件 | 使用场景 |
| 16 | Isolate 是什么？ | 独立内存/事件循环；消息通信；CPU 密集 | 和 async 区别 |

| 19 | Flutter 性能优化？ | const/拆 Widget/RepaintBoundary/ListView.builder/Isolate/profile | 怎么定位 |
| 20 | Impeller 是什么？ | 新渲染引擎，预编译 shader，减少首帧卡顿 | 和 Skia 区别 |

| 24 | Flutter 包体积为什么大？ | 自带引擎和运行时；split-per-abi/混淆/资源优化 | 能减到多少 |

**口语模板（Flutter vs RN）：**

> 看团队和业务。前端团队、想复用 React 能力、依赖大量原生生态，选 RN 更顺；要求各端 UI 高度一致、动画复杂、团队愿意学 Dart，选 Flutter 更合适；需要深度平台能力或极致性能，还是原生。Flutter 的优势是自绘引擎和一致性，代价是包体积和 Dart 学习成本；RN 的优势是生态和前端上手快，代价是原生组件差异和桥/JSI 的通信成本。

## 14. 延伸追问怎么接

面试官不会只问一个问题，通常会顺着你的回答往下挖。你要提前准备“追问链”。

### 14.1 常见追问链

**React Hooks：**

```text
你用过哪些 Hooks？
  → useEffect 依赖为空会怎样？
    → 那闭包陷阱是什么？
      → 怎么解决？（函数式更新 / useRef）
        → 为什么函数式更新能拿到最新值？
```

**RN 列表：**

```text
FlatList 怎么优化？
  → getItemLayout 原理？
    → 行高不固定怎么办？
      → removeClippedSubviews 有什么坑？
```

**小程序：**

```text
setData 为什么慢？
  → 路径更新为什么快？
    → 数据量很大怎么办？
      → 分包和 setData 有关系吗？
```

**工程化：**

```text
Webpack 怎么优化？
  → tree shaking 原理？
    → 为什么 CommonJS 不行？
      → sideEffects 是什么？
```

### 14.2 接追问的三步法

1. **确认问题**：`“您问的是 A 还是 B？”` 避免答偏。
2. **分层回答**：`“我从三个层面说：是什么、为什么、项目里怎么做。”`
3. **主动收尾**：`“这块我实践到的边界是……再往下我没有深入。”`

### 14.3 追问时的加分句

- `“这块我踩过一个坑……”`（讲具体问题）
- `“我们当时对比了 A 和 B，最后选 B，因为……”`（体现取舍）
- `“上线后我们用 X 指标验证，从 A 到 B。”`（体现结果）
- `“如果重做，我会……”`（体现复盘）
- `“这个点我了解得不够深，我的推测是……但需要验证。”`（诚实 + 思路）

## 15. 不会的问题怎么答

### 15.1 三种话术

**完全不会：**

> 这个点我目前没有实际用过，不敢乱说。我理解它和 `[相邻知识]` 有关，如果是我的话，我会从 `[思路]` 入手验证。这块我回去会补一下。

**有点印象：**

> 我确认一下，您问的是 `[A]` 还是 `[B]`？如果是 A，我的理解是 `[核心点]`，但细节我可能记得不准。

**被追问到底：**

> 到这一步我没有更深的实践了。我的推测是 `[假设]`，但需要看源码/做实验验证。我不想编一个答案。

### 15.2 被质疑时

> 您说的这个风险确实存在。我们当时的考虑是 `[背景/约束]`，所以选了 `[方案]`。数据上是 `[结果]`。如果现在重做，我会 `[改进]`。

**不要：**

- 和面试官争对错。
- 硬编一个不存在的经历。
- 说“我们公司就是这样”。
- 把问题推给队友/后端。

### 15.3 压力面

- 保持语速，不要急着反驳。
- 先复述问题，确认对方在问什么。
- 用事实、数据、取舍回答。
- 不会就承认，不卑不亢。
- 面试是双向选择，不必讨好。

## 16. 眼神与肢体语言（现场 + 视频）

> 这部分常被忽略，但它直接影响面试官对你的“可信度”和“沟通感”。

### 16.1 现场面试

| 场景 | 做法 |
|---|---|
| 进入/问好 | 微笑、点头、眼神看对方，坐下前说“您好” |
| 回答时 | 看提问者的**双眼到鼻尖三角区**，每 3-5 秒自然移动一次 |
| 多人面试 | 主要看提问者，每句话结尾扫视其他人，不要只盯一个人 |
| 思考时 | 看斜上方或桌面 1-2 秒，然后回到对方眼睛，说“我想一下” |
| 卡壳时 | 眼神不要躲，停顿 2 秒，说“我整理一下”，再结构化回答 |
| 被追问 | 保持眼神，点头，等对方说完再答，不打断 |
| 被质疑 | 看着对方，先复述，再给事实，不翻白眼/撇嘴 |
| 紧张时 | 深呼吸，手放桌面，放慢语速，喝一口水 |

**不要：**

- 长时间盯天花板/地板/手机/手表。
- 眼神飘忽、频繁眨眼、翻白眼。
- 抱臂、抖腿、转笔、抠手。
- 用手指人、拍桌子。
- 假笑、皱眉、叹气。

### 16.2 视频面试

| 事项 | 做法 |
|---|---|
| 眼神 | **看摄像头**，不是看屏幕上的对方，也不是看自己 |
| 自见窗口 | 关掉或移开，避免分心 |
| 摄像头高度 | 与眼睛齐平，不要仰拍/俯拍 |
| 光线 | 光源在正面，不要背光 |
| 背景 | 干净、安静、无杂物 |
| 设备 | 耳机 + 稳定网络，提前测试 |
| 看笔记 | 可以贴关键词在摄像头旁，但不要低头念 |
| 手势 | 保持在镜头内，不要太大 |
| 姿态 | 坐直，身体略微前倾 |

### 16.3 声音与表达

- 音量比平时略大，语速比平时慢 10-20%。
- 用停顿代替“嗯、那个、然后”。
- 一句话不超过 20 秒，长答案先给结论。
- 重要数字/关键词放慢、加重。
- 不要背稿，像在讲给同事听。

### 16.4 练习方法

1. 手机录像回答 3 个高频题，回看眼神、手势、口头禅。
2. 对着镜子讲 2 分钟自我介绍。
3. 找朋友模拟面试，让对方打断、追问。
4. 计时：自我介绍 90 秒，项目 3 分钟。
5. 录音回听，删掉“然后/就是/那个”。

### 16.5 不同场景的眼神策略

| 场景 | 眼神 |
|---|---|
| 自我介绍 | 看主面试官，结尾扫视 |
| 讲项目 | 看提问者，讲到数据时看对方反应 |
| 思考 | 短暂移开，不要长时间躲闪 |
| 不会 | 看着对方说“这块我没深入”，不要低头 |
| 被质疑 | 稳定注视，先听完，再回答 |
| 反问 | 看对方，表现出兴趣 |
| 结束 | 微笑、点头、道谢 |

## 20. 面试后

1. 当天发一条感谢信息（HR 或面试官，简短）。
2. 记录被问到的题，标出不会的。
3. 24 小时内补齐不会的知识点。
4. 复盘表达：哪里卡了、哪里啰嗦、哪里眼神不对。
5. 如果一周没消息，可以礼貌询问进度。
6. 不要同时把话说死，保留其他机会。

**感谢信息模板：**

> 您好，我是今天面试 `[岗位]` 的 `[姓名]`。感谢您的时间，今天聊到 `[一个具体点]` 让我对团队和业务有了更多了解。如果有需要补充的材料，随时联系我。期待有机会加入。

## 21. 最后：面试的底层逻辑

面试官不是在找“完美的人”，而是在判断三件事：

1. **你能不能把活干出来？**（基础 + 项目 + 手写）
2. **你靠不靠谱？**（诚实 + 复盘 + 沟通）
3. **和你共事累不累？**（表达 + 眼神 + 态度）

所以：

- 不会的题，诚实说，比编答案加分。
- 项目讲清楚“你做了什么、为什么、结果”，比堆名词加分。
- 眼神稳定、语速放慢、先给结论，比背稿加分。
- 面试是双向选择，不卑不亢。

**祝你面试顺利。**
