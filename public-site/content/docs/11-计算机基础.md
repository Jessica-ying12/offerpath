# 第一部分：计算机组成

## 1. 计算机的基本结构 ⭐

```text
CPU（运算器 + 控制器 + 寄存器 + 缓存）
  ↕ 总线
内存（RAM）
  ↕
硬盘/SSD（外存）
  ↕
输入/输出设备（键盘、屏幕、网卡）
```

- **CPU**：执行指令。
- **内存**：临时存放程序和数据，断电丢失。
- **硬盘**：持久化存储，速度比内存慢几个数量级。
- **缓存**：CPU 和内存之间的高速小容量存储（L1/L2/L3）。

### 1.1 为什么要有缓存

CPU 很快，内存相对慢。缓存利用**局部性原理**：

- 时间局部性：刚访问的数据，很可能马上再访问。
- 空间局部性：访问了 `arr[i]`，很可能访问 `arr[i+1]`。

所以：

```js
// 好：顺序访问，缓存命中率高
for (let i = 0; i < arr.length; i++) sum += arr[i];

// 差：跳跃访问，缓存命中率低
for (let i = 0; i < arr.length; i += 1000) sum += arr[i];
```

前端里，长列表虚拟滚动、连续内存、对象属性稳定，都是类似的局部性思想。

### 1.2 二进制、字节、进制

```text
1 bit = 0 或 1
1 byte = 8 bit
1 KB = 1024 B
1 MB = 1024 KB
1 GB = 1024 MB
```

```js
0b1010;   // 二进制 10
0o12;     // 八进制 10
0x0a;     // 十六进制 10
(10).toString(2);  // '1010'
parseInt('1010', 2); // 10
```

### 1.3 整数表示：原码、反码、补码 ⭐

计算机用**补码**表示有符号整数：

- 正数：原码 = 反码 = 补码。
- 负数：反码 = 原码符号位不变、其余取反；补码 = 反码 + 1。
- 好处：减法可以变成加法，0 只有一种表示。

8 位有符号整数范围：`-128 ~ 127`。

```text
-1 的原码：1000 0001
-1 的反码：1111 1110
-1 的补码：1111 1111
```

### 1.4 浮点数：IEEE 754 ⭐⭐

JS 的 `number` 是**双精度浮点数**：

```text
64 位 = 1 位符号 + 11 位指数 + 52 位尾数
```

很多十进制小数无法用二进制精确表示，所以：

```js
0.1 + 0.2 === 0.3; // false
// 0.30000000000000004
```

解决：金额用整数（分），或 `toFixed` 展示，或 `decimal.js`。

### 1.5 字符编码：ASCII、Unicode、UTF-8 ⭐⭐

- ASCII：0-127，英文/数字/符号，1 字节。
- Unicode：给世界上每个字符一个编号（码点），例如 `中` = U+4E2D。
- UTF-8：Unicode 的一种变长编码，1-4 字节，ASCII 兼容。
  - 英文 1 字节。
  - 中文通常 3 字节。
  - emoji 通常 4 字节。

```js
'中'.length; // 1（UTF-16 码元）
'😀'.length; // 2（代理对）
[...'😀'].length; // 1（按码点）
```

前端坑：字符串长度、截断 emoji、URL 编码（`encodeURIComponent`）。

### 1.6 大小端 ⭐

多字节数据在内存中的字节顺序：

- 大端：高位字节在前。
- 小端：低位字节在前。

网络传输通常用大端（网络字节序）。日常前端开发很少直接处理，但面试可能问。

## 2. 进程、线程、协程 ⭐⭐⭐

### 2.1 进程 vs 线程

| 维度 | 进程 | 线程 |
|---|---|---|
| 地址空间 | 独立 | 同一进程内共享 |
| 资源 | 独立文件/内存 | 共享代码、数据、堆 |
| 栈/寄存器 | 独立 | 每个线程独立 |
| 切换成本 | 高 | 较低 |
| 通信 | IPC（管道/消息/共享内存） | 共享内存 + 同步 |
| 崩溃影响 | 通常不影响其他进程 | 可能导致整个进程崩溃 |

```text
进程 = 一个工厂
线程 = 工厂里的工人
```

浏览器：

- 每个标签页通常一个渲染进程（现代浏览器可能多进程）。
- 一个进程里有主线程、合成线程、光栅线程、IO 线程等。
- JS 主线程是单线程的（见 03 事件循环）。

### 2.2 进程状态

```text
新建 → 就绪 → 运行 → 阻塞 → 就绪 → 运行 → 终止
```

- 就绪：等待 CPU。
- 运行：占用 CPU。
- 阻塞：等待 I/O/事件。

### 2.3 上下文切换 ⭐

CPU 从一个进程/线程切换到另一个，需要保存当前寄存器、程序计数器、栈指针等，再恢复另一个的。

- 切换有开销。
- 线程不是越多越好，频繁切换会降低性能。
- 前端：Web Worker、RN 的 JS 线程/UI 线程、Flutter 的 Isolate，都是并行的手段，但通信有成本。

### 2.4 用户态与内核态 ⭐

- 用户态：应用程序运行，权限受限。
- 内核态：操作系统内核运行，可访问硬件。
- 系统调用：用户态请求内核提供服务（读文件、发网络包、创建线程）。

为什么提这个：面试问“为什么 IO 操作昂贵”“为什么系统调用有开销”，都和安全/上下文切换有关。

## 3. 内存 ⭐⭐

### 3.1 栈 vs 堆

| 维度 | 栈 | 堆 |
|---|---|---|
| 管理 | 系统自动 | 手动/GC |
| 速度 | 快 | 较慢 |
| 大小 | 小 | 大 |
| 存放 | 局部变量、函数调用帧 | 对象、闭包、大数组 |
| 生命周期 | 函数结束即释放 | 由 GC 决定 |
| 问题 | 栈溢出（递归太深） | 内存泄漏、碎片 |

```js
function foo() {
  const a = 1;          // 栈（原始值）
  const obj = { b: 2 }; // obj 引用在栈，对象在堆
}
```

### 3.2 虚拟内存 ⭐⭐

每个进程看到的是**虚拟地址空间**，由操作系统映射到物理内存。

- 页表：虚拟页 → 物理页。
- TLB：页表缓存，加速地址转换。
- 缺页中断（page fault）：访问的页不在内存，从磁盘换入。
- 页面置换：LRU、FIFO、Clock。
- 抖动（thrashing）：频繁换页，性能急剧下降。

好处：隔离、安全、可以运行比物理内存更大的程序。

### 3.3 内存泄漏与 GC

见 03 文档第 21 节。核心：

- 标记-清除：从根对象标记可达对象，回收不可达的。
- 分代回收：新生代/老生代。
- 泄漏：全局变量、定时器、监听器、闭包、Detached DOM、Map 键。

## 4. I/O 模型 ⭐⭐

```text
阻塞 I/O：调用后一直等，直到数据就绪
非阻塞 I/O：立即返回，轮询
I/O 多路复用：select/poll/epoll，一个线程管理多个 fd
信号驱动 I/O
异步 I/O：内核完成后通知
```

### 4.1 select / poll / epoll

| 方式 | 特点 |
|---|---|
| select | fd 集合有上限，每次线性扫描 |
| poll | 没有上限，仍然线性扫描 |
| epoll | 事件驱动，只返回就绪的 fd，适合大量连接（Linux） |

Node.js 的 libuv 在 Linux 上用 epoll，macOS 用 kqueue，Windows 用 IOCP。这就是 Node 能高并发处理 I/O 的底层原因之一。

### 4.2 零拷贝 ⭐

传统文件发送：磁盘 → 内核缓冲区 → 用户缓冲区 → socket 缓冲区 → 网卡。

零拷贝（sendfile/mmap）减少用户态/内核态拷贝，提高吞吐。Nginx、Kafka 常用。前端了解概念即可。

# 第二部分：数据结构

## 5. 复杂度 ⭐⭐⭐

大 O 表示法：忽略常数和低阶项，描述输入规模 n 增大时，时间/空间的增长趋势。

| 复杂度 | 名称 | 例子 |
|---|---|---|
| O(1) | 常数 | 数组下标、哈希表平均查找 |
| O(log n) | 对数 | 二分查找、平衡树 |
| O(n) | 线性 | 遍历数组 |
| O(n log n) | 线性对数 | 归并/快速/堆排序 |
| O(n²) | 平方 | 双重循环、冒泡排序 |
| O(2ⁿ) | 指数 | 递归斐波那契（未优化） |
| O(n!) | 阶乘 | 全排列 |

**注意：**

- 大 O 看最坏情况（有时看平均/摊还）。
- 常数项在实际中也可能很重要。
- 空间复杂度也算。

## 6. 数组与链表 ⭐⭐⭐

### 6.1 数组

- 连续内存。
- 随机访问 O(1)。
- 中间插入/删除 O(n)（要移动元素）。
- 末尾插入/删除均摊 O(1)。
- 缓存友好（局部性好）。

```js
const arr = [1, 2, 3];
arr[1];          // O(1)
arr.push(4);     // 均摊 O(1)
arr.unshift(0);  // O(n)
arr.splice(1, 1);// O(n)
```

### 6.2 链表

- 节点分散在内存，每个节点存 next（和 prev）。
- 查找 O(n)。
- 已知节点时插入/删除 O(1)。
- 缓存不友好。

```js
class ListNode {
  constructor(val, next = null) {
    this.val = val;
    this.next = next;
  }
}
```

| 操作 | 数组 | 链表 |
|---|---|---|
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n) | O(1) |
| 尾部插入 | 均摊 O(1) | O(1)（有尾指针） |
| 中间插入 | O(n) | O(1)（已知前驱） |
| 内存 | 连续 | 分散 |
| 缓存 | 好 | 差 |

**前端场景：**

- 数组：列表渲染、`map/filter`、栈/队列（小数据）。
- 链表：LRU、React Fiber 树（child/sibling/return 指针）、undo/redo。

## 7. 栈与队列 ⭐⭐⭐

### 7.1 栈（LIFO）

```js
const stack = [];
stack.push(1);
stack.push(2);
stack.pop(); // 2
stack[stack.length - 1]; // 栈顶
```

应用：函数调用栈、括号匹配、撤销、浏览器历史、DFS。

### 7.2 队列（FIFO）

```js
const queue = [];
queue.push(1);
queue.push(2);
queue.shift(); // 1，O(n)
```

大数据量用双端队列/头指针：

```js
class Queue {
  constructor() {
    this.items = [];
    this.head = 0;
  }
  enqueue(x) { this.items.push(x); }
  dequeue() {
    if (this.head >= this.items.length) return undefined;
    const value = this.items[this.head++];
    if (this.head > 1000) {
      this.items = this.items.slice(this.head);
      this.head = 0;
    }
    return value;
  }
  get size() { return this.items.length - this.head; }
}
```

应用：BFS、任务队列、消息队列、事件循环的任务队列。

## 8. 哈希表 ⭐⭐⭐

哈希表通过哈希函数把 key 映射到数组下标。

- 平均查找/插入/删除：O(1)。
- 最坏：O(n)（所有 key 冲突）。
- 冲突解决：链地址法（拉链）、开放寻址。
- 负载因子：元素数/桶数，太高要扩容。

```js
const map = new Map();
map.set('a', 1);
map.get('a');
map.has('a');
map.delete('a');
```

### JS 里 Object vs Map

| 维度 | Object | Map |
|---|---|---|
| key 类型 | string/Symbol | 任意类型 |
| 顺序 | 整数键特殊排序 | 插入顺序 |
| 大小 | 无直接 size | `map.size` |
| 原型键 | 有原型链干扰 | 无 |
| 频繁增删 | 一般 | 更优 |
| 遍历 | `Object.keys` | 可迭代 |

**前端场景：**

- 缓存（接口结果、组件映射）。
- 计数（字符频率、词频）。
- 去重（Set）。
- 路由表、权限表。

## 9. 树 ⭐⭐⭐

### 9.1 二叉树

```js
class TreeNode {
  constructor(val, left = null, right = null) {
    this.val = val;
    this.left = left;
    this.right = right;
  }
}
```

遍历：

```js
// 前序：根 → 左 → 右
function preorder(node, result = []) {
  if (!node) return result;
  result.push(node.val);
  preorder(node.left, result);
  preorder(node.right, result);
  return result;
}

// 中序：左 → 根 → 右（BST 得到有序序列）
function inorder(node, result = []) {
  if (!node) return result;
  inorder(node.left, result);
  result.push(node.val);
  inorder(node.right, result);
  return result;
}

// 后序：左 → 右 → 根
function postorder(node, result = []) {
  if (!node) return result;
  postorder(node.left, result);
  postorder(node.right, result);
  result.push(node.val);
  return result;
}

// 层序：BFS
function levelOrder(root) {
  if (!root) return [];
  const result = [];
  const queue = [root];
  while (queue.length) {
    const level = [];
    const size = queue.length;
    for (let i = 0; i < size; i++) {
      const node = queue.shift();
      level.push(node.val);
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    result.push(level);
  }
  return result;
}
```

### 9.2 二叉搜索树（BST）

- 左子树所有节点 < 根 < 右子树所有节点。
- 平均查找 O(log n)，最坏 O(n)（退化成链表）。
- 中序遍历有序。

### 9.3 平衡树

- AVL：严格平衡，查找快，插入/删除旋转多。
- 红黑树：近似平衡，插入/删除旋转少；Java TreeMap、C++ map 常用。
- 前端：`Map`/`Set` 的底层实现因引擎而异，不必死记。

### 9.4 堆

- 完全二叉树。
- 大顶堆：父 ≥ 子；小顶堆：父 ≤ 子。
- 插入/删除 O(log n)，建堆 O(n)，取堆顶 O(1)。
- 应用：优先队列、Top K、任务调度。

```js
class MinHeap {
  constructor() { this.data = []; }
  push(val) {
    this.data.push(val);
    this.bubbleUp(this.data.length - 1);
  }
  pop() {
    if (this.data.length === 0) return undefined;
    const top = this.data[0];
    const last = this.data.pop();
    if (this.data.length > 0) {
      this.data[0] = last;
      this.bubbleDown(0);
    }
    return top;
  }
  bubbleUp(i) {
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.data[parent] <= this.data[i]) break;
      [this.data[parent], this.data[i]] = [this.data[i], this.data[parent]];
      i = parent;
    }
  }
  bubbleDown(i) {
    const n = this.data.length;
    while (true) {
      let smallest = i;
      const left = i * 2 + 1;
      const right = i * 2 + 2;
      if (left < n && this.data[left] < this.data[smallest]) smallest = left;
      if (right < n && this.data[right] < this.data[smallest]) smallest = right;
      if (smallest === i) break;
      [this.data[smallest], this.data[i]] = [this.data[i], this.data[smallest]];
      i = smallest;
    }
  }
}
```

### 9.5 图

- 有向/无向、带权/无权。
- 存储：邻接表（稀疏）、邻接矩阵（稠密）。
- 遍历：BFS、DFS。
- 应用：社交关系、依赖图、路由、课程表。

## 11. 排序 ⭐⭐⭐

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|---|---|---|---|---|---|
| 冒泡 | O(n²) | O(n²) | O(1) | 是 | 教学用，实际少 |
| 选择 | O(n²) | O(n²) | O(1) | 否 | 交换次数少 |
| 插入 | O(n²) | O(n²) | O(1) | 是 | 小数组/近乎有序很快 |
| 归并 | O(n log n) | O(n log n) | O(n) | 是 | 稳定，适合链表/外部排序 |
| 快速 | O(n log n) | O(n²) | O(log n) | 否 | 实际最快之一，注意 pivot |
| 堆 | O(n log n) | O(n log n) | O(1) | 否 | 适合 Top K |

**稳定**：相等元素的相对顺序不变。

```js
// JS 的 sort 默认按字符串排序，且不保证稳定（现代引擎实际稳定）
[10, 2, 1].sort(); // [1, 10, 2]
[10, 2, 1].sort((a, b) => a - b); // [1, 2, 10]
```

## 12. 二分查找 ⭐⭐⭐

前提：数组有序。

```js
function binarySearch(arr, target) {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    // 防止 (left + right) 溢出
    const mid = left + ((right - left) >> 1);

    if (arr[mid] === target) return mid;
    if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }

  return -1;
}
```

变体：

- 找第一个 ≥ target 的位置。
- 找最后一个 ≤ target 的位置。
- 旋转数组找最小值。
- 二分答案（最大化最小值/最小化最大值）。

## 13. 双指针与滑动窗口 ⭐⭐⭐

### 13.1 双指针

```js
// 有序数组两数之和
function twoSumSorted(nums, target) {
  let left = 0;
  let right = nums.length - 1;

  while (left < right) {
    const sum = nums[left] + nums[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;
    else right--;
  }

  return [];
}
```

### 13.2 滑动窗口

```js
// 最长无重复子串
function lengthOfLongestSubstring(s) {
  const lastIndex = new Map();
  let left = 0;
  let max = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];

    if (lastIndex.has(ch) && lastIndex.get(ch) >= left) {
      left = lastIndex.get(ch) + 1;
    }

    lastIndex.set(ch, right);
    max = Math.max(max, right - left + 1);
  }

  return max;
}
```

适用：连续子数组/子串，满足某种条件的最长/最短。

## 14. BFS / DFS ⭐⭐⭐

### 14.1 BFS（广度优先）

```js
function bfs(graph, start) {
  const visited = new Set([start]);
  const queue = [start];
  const order = [];
  let head = 0;

  while (head < queue.length) {
    const node = queue[head++];
    order.push(node);

    for (const next of graph[node] || []) {
      if (!visited.has(next)) {
        visited.add(next);
        queue.push(next);
      }
    }
  }

  return order;
}
```

- 用队列。
- 适合最短路径（无权图）、层序遍历。
- 复杂度 O(V + E)。

### 14.2 DFS（深度优先）

```js
function dfs(graph, start, visited = new Set(), order = []) {
  if (visited.has(start)) return order;

  visited.add(start);
  order.push(start);

  for (const next of graph[start] || []) {
    dfs(graph, next, visited, order);
  }

  return order;
}
```

- 用栈/递归。
- 适合连通性、拓扑排序、回溯。
- 复杂度 O(V + E)。
- 递归太深会栈溢出，可改迭代。

## 15. 动态规划 ⭐⭐⭐

适用条件：

1. **重叠子问题**：同一个子问题被重复计算。
2. **最优子结构**：大问题的最优解由子问题的最优解组成。

解题步骤：

```text
1. 定义 dp[i] 的含义
2. 找状态转移方程
3. 找初始值
4. 确定遍历顺序
5. 空间优化（滚动数组）
```

### 15.1 爬楼梯

```js
function climbStairs(n) {
  if (n <= 2) return n;

  let a = 1; // dp[1]
  let b = 2; // dp[2]

  for (let i = 3; i <= n; i++) {
    [a, b] = [b, a + b];
  }

  return b;
}
```

### 15.2 零钱兑换

```js
function coinChange(coins, amount) {
  // dp[i] = 凑出金额 i 的最少硬币数
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;

  for (let i = 1; i <= amount; i++) {
    for (const coin of coins) {
      if (i >= coin) {
        dp[i] = Math.min(dp[i], dp[i - coin] + 1);
      }
    }
  }

  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

### 15.3 最长递增子序列（LIS）

```js
function lengthOfLIS(nums) {
  const dp = new Array(nums.length).fill(1);

  for (let i = 1; i < nums.length; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }

  return Math.max(...dp, 0);
}
// O(n²)；有 O(n log n) 的二分+贪心解法
```

## 16. 贪心与回溯 ⭐⭐

### 16.1 贪心

每一步选局部最优，期望得到全局最优。不是所有问题都适用。

例子：区间调度、找零（特定币种）、跳跃游戏。

### 16.2 回溯

```js
// 全排列
function permute(nums) {
  const result = [];
  const path = [];
  const used = new Array(nums.length).fill(false);

  function dfs() {
    if (path.length === nums.length) {
      result.push([...path]);
      return;
    }

    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;

      used[i] = true;
      path.push(nums[i]);
      dfs();
      path.pop();
      used[i] = false;
    }
  }

  dfs();
  return result;
}
```

模板：

```text
选择 → 递归 → 撤销选择
```

### 17.4 合并两个有序链表

```js
function mergeTwoLists(a, b) {
  const dummy = { next: null };
  let tail = dummy;

  while (a && b) {
    if (a.val <= b.val) {
      tail.next = a;
      a = a.next;
    } else {
      tail.next = b;
      b = b.next;
    }
    tail = tail.next;
  }

  tail.next = a || b;
  return dummy.next;
}
```

```js
    fast = fast.next.next;

}
```

### 17.6 快速排序

```js
function quickSort(arr) {
  if (arr.length <= 1) return arr;

  const pivot = arr[Math.floor(arr.length / 2)];
  const left = [];
  const equal = [];
  const right = [];

  for (const n of arr) {
    if (n < pivot) left.push(n);
    else if (n > pivot) right.push(n);
    else equal.push(n);
  }

  return [...quickSort(left), ...equal, ...quickSort(right)];
}
```

### 17.7 归并排序

```js
function mergeSort(arr) {
  if (arr.length <= 1) return arr;

  const mid = arr.length >> 1;
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));

  const result = [];
  let i = 0;
  let j = 0;

  while (i < left.length && j < right.length) {
    result.push(left[i] <= right[j] ? left[i++] : right[j++]);
  }

  return result.concat(left.slice(i), right.slice(j));
}
```

### 17.8 LRU 缓存

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map(); // Map 保持插入顺序
  }

  get(key) {
    if (!this.map.has(key)) return -1;

    const value = this.map.get(key);
    this.map.delete(key);
    this.map.set(key, value); // 移到末尾，表示最近使用
    return value;
  }

  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);

    if (this.map.size > this.capacity) {
      // 删除最久未使用的（Map 的第一个 key）
      const oldestKey = this.map.keys().next().value;
      this.map.delete(oldestKey);
    }
  }
}
```

### 17.9 合并区间

```js
function mergeIntervals(intervals) {
  if (intervals.length === 0) return [];

  intervals.sort((a, b) => a[0] - b[0]);
  const result = [intervals[0].slice()];

  for (let i = 1; i < intervals.length; i++) {
    const last = result[result.length - 1];
    const [start, end] = intervals[i];

    if (start <= last[1]) {
      last[1] = Math.max(last[1], end);
    } else {
      result.push([start, end]);
    }
  }

  return result;
}
```

### 17.11 岛屿数量（DFS）

```js
function numIslands(grid) {
  let count = 0;

  function dfs(i, j) {
    if (
      i < 0 || i >= grid.length ||
      j < 0 || j >= grid[0].length ||
      grid[i][j] !== '1'
    ) {
      return;
    }

    grid[i][j] = '0'; // 标记已访问
    dfs(i + 1, j);
    dfs(i - 1, j);
    dfs(i, j + 1);
    dfs(i, j - 1);
  }

  for (let i = 0; i < grid.length; i++) {
    for (let j = 0; j < grid[0].length; j++) {
      if (grid[i][j] === '1') {
        count++;
        dfs(i, j);
      }
    }
  }

  return count;
}
```

```js
function levelOrder(root) {
  if (!root) return [];

  const result = [];
  const queue = [root];

  while (queue.length) {
    const level = [];
    const size = queue.length;

    for (let i = 0; i < size; i++) {
      const node = queue.shift();
      level.push(node.val);
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }

    result.push(level);
  }

  return result;
}
```

```js
}
```

```js
class MinStack {
  constructor() {
    this.stack = [];
    this.minStack = [];
  }

  push(val) {
    this.stack.push(val);
    const min = this.minStack.length === 0
      ? val
      : Math.min(val, this.minStack[this.minStack.length - 1]);
    this.minStack.push(min);
  }

  pop() {
    this.minStack.pop();
    return this.stack.pop();
  }

  top() {
    return this.stack[this.stack.length - 1];
  }

  getMin() {
    return this.minStack[this.minStack.length - 1];
  }
}
```

## 18. 线程同步与死锁 ⭐⭐⭐

### 18.1 竞态条件

多个线程同时读写共享数据，结果依赖执行顺序。

```js
let count = 0;
// 两个线程同时 count++，可能丢失更新
```

解决：互斥锁、原子操作、消息传递。

### 18.2 互斥锁 vs 信号量

| 机制 | 作用 |
|---|---|
| 互斥锁（mutex） | 同一时刻只允许一个线程进入临界区 |
| 信号量（semaphore） | 控制同时访问的线程数量（计数） |
| 条件变量 | 等待某个条件成立 |
| 读写锁 | 读共享、写独占 |

### 18.3 死锁的四个必要条件 ⭐⭐⭐

1. **互斥**：资源一次只能被一个线程占用。
2. **持有并等待**：持有资源同时等待其他资源。
3. **不可剥夺**：资源只能由持有者释放。
4. **循环等待**：形成等待环。

解决：

- 破坏任意一个条件。
- 按固定顺序加锁（破坏循环等待）。
- 超时释放（破坏不可剥夺）。
- 一次性申请所有资源（破坏持有并等待）。
- 死锁检测与恢复。

### 18.4 活锁与饥饿

- 活锁：线程一直重试，但无法推进。
- 饥饿：低优先级线程长期拿不到资源。

## 19. 浏览器是多进程还是多线程 ⭐⭐

现代浏览器：

- **Browser 进程**：主控。
- **Renderer 进程**：每个标签页一个（或按站点隔离）。
- **GPU 进程**：合成、绘制。
- **Network 进程**：网络请求。
- **Plugin/Utility 进程**。

Renderer 进程内：

- **主线程**：JS、DOM、样式、布局。
- **合成线程**：滚动、合成。
- **光栅线程**：把图层转成像素。

这就是为什么：

- JS 阻塞主线程会卡 UI。
- CSS transform/opacity 可以走合成线程。
- Web Worker 不能直接操作 DOM。

## 21. TCP vs UDP ⭐⭐⭐

| 维度 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠（确认/重传） | 不可靠 |
| 顺序 | 保证顺序 | 不保证 |
| 速度 | 较慢 | 快 |
| 头部 | 20 字节起 | 8 字节 |
| 流量/拥塞控制 | 有 | 无 |
| 场景 | HTTP、文件、聊天 | 视频、游戏、DNS、直播 |

### 21.1 三次握手

```text
客户端 → 服务端：SYN，seq=x
服务端 → 客户端：SYN+ACK，seq=y，ack=x+1
客户端 → 服务端：ACK，ack=y+1
```

为什么是三次：双方都要确认“我能发、你能收；你能发、我能收”，两次不够。

### 21.2 四次挥手

```text
主动方 → 被动方：FIN
被动方 → 主动方：ACK
被动方 → 主动方：FIN
主动方 → 被动方：ACK
主动方等待 2MSL 后关闭
```

为什么四次：TCP 是全双工，两个方向要分别关闭。

### 21.3 可靠传输

- 序号 + 确认（ACK）。
- 超时重传。
- 校验和。
- 流量控制（滑动窗口）。
- 拥塞控制（慢启动、拥塞避免、快重传、快恢复）。

## 22. HTTP ⭐⭐⭐

### 22.1 HTTP/1.1

- 持久连接（keep-alive）。
- 管道化（pipelining）有队头阻塞。
- 每个域名并发连接数有限（浏览器通常 6 个）。

### 22.2 HTTP/2

- 二进制分帧。
- 多路复用：一个连接上并行多个请求，解决 HTTP 队头阻塞。
- 头部压缩（HPACK）。
- 服务器推送（server push，实际使用少）。
- 仍有 TCP 层队头阻塞（丢包会影响所有流）。

### 22.3 HTTP/3

- 基于 QUIC（UDP）。
- 0-RTT/1-RTT 握手。
- 解决 TCP 队头阻塞。
- 连接迁移（切换网络不断连）。
- 需要浏览器/服务器支持。

## 23. HTTPS 与 TLS ⭐⭐⭐

HTTPS = HTTP + TLS。

流程（简化）：

1. 客户端发送支持的 TLS 版本/加密套件 + 随机数。
2. 服务端返回证书 + 随机数 + 选定的套件。
3. 客户端验证证书（CA 签名、域名、有效期）。
4. 双方用非对称加密/密钥交换协商出对称密钥。
5. 之后用对称密钥加密通信。

为什么用混合加密：

- 非对称加密安全但慢，适合交换密钥。
- 对称加密快，适合传输数据。

证书作用：证明“这个公钥确实属于这个域名”，防止中间人攻击。

## 28. 关系型数据库基础 ⭐⭐

表、行、列、主键、外键、索引。

```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL,
  email VARCHAR(100) UNIQUE,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP

CREATE TABLE orders (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,

  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id)

```

### 28.1 常用 SQL

```sql
-- 查询
SELECT id, name FROM users WHERE id = 1;

-- 模糊查询
SELECT * FROM users WHERE name LIKE '张%';

-- 排序 + 分页
SELECT * FROM orders ORDER BY created_at DESC LIMIT 20 OFFSET 0;

-- 聚合
SELECT user_id, COUNT(*) AS cnt, SUM(amount) AS total
FROM orders
GROUP BY user_id
HAVING total > 1000;

-- 连接
SELECT u.name, o.amount
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
WHERE u.id = 1;

-- 插入
INSERT INTO users (name, email) VALUES ('Tom', 'tom@example.com');

-- 更新
UPDATE users SET name = 'Jerry' WHERE id = 1;

-- 删除
DELETE FROM users WHERE id = 1;
```

### 28.2 JOIN

| 类型 | 含义 |
|---|---|
| INNER JOIN | 两边都匹配 |
| LEFT JOIN | 左表全保留，右表没有为 NULL |
| RIGHT JOIN | 右表全保留 |
| FULL JOIN | 两边都保留（MySQL 不直接支持，用 UNION） |

## 29. 索引 ⭐⭐⭐

索引像书的目录，加速查询。

- 常见结构：B+ 树。
- 主键索引（聚簇索引）：叶子节点存整行数据。
- 二级索引：叶子节点存主键，需要回表。
- 覆盖索引：查询字段都在索引里，不用回表。
- 联合索引：遵守**最左前缀**。
- 索引会加速读，但降低写速度、占空间。

```sql
CREATE INDEX idx_orders_user_time ON orders(user_id, created_at);
```

能用到 `(user_id, created_at)` 的查询：

```sql
WHERE user_id = 1
WHERE user_id = 1 AND created_at > '2026-01-01'
WHERE user_id = 1 ORDER BY created_at
```

用不到：

```sql
WHERE created_at > '2026-01-01' -- 跳过了最左列
```

### 29.1 B+ 树为什么适合数据库

- 高度低（3-4 层就能存千万级），磁盘 I/O 少。
- 叶子节点有序且用链表连接，范围查询快。
- 非叶子节点只存键，能放更多索引项。

### 29.2 索引失效

- 对索引列做函数/运算：`WHERE YEAR(created_at) = 2026`。
- 隐式类型转换：字符串列用数字查。
- `LIKE '%xx'` 前导模糊。
- `OR` 两边没有都走索引。
- 不符合最左前缀。

## 30. 事务与隔离级别 ⭐⭐⭐

### 30.1 ACID

| 特性 | 含义 |
|---|---|
| 原子性 Atomicity | 要么全成功，要么全失败 |
| 一致性 Consistency | 事务前后数据满足约束 |
| 隔离性 Isolation | 并发事务互不干扰 |
| 持久性 Durability | 提交后永久保存 |

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

### 30.2 并发问题

| 问题 | 含义 |
|---|---|
| 脏读 | 读到未提交的数据 |
| 不可重复读 | 同一事务内两次读同一行，结果不同 |
| 幻读 | 同一事务内两次范围查询，行数不同 |

### 30.3 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| 读未提交 | 可能 | 可能 | 可能 |
| 读已提交 | 否 | 可能 | 可能 |
| 可重复读 | 否 | 否 | 可能（InnoDB 用 MVCC + 间隙锁基本解决） |
| 串行化 | 否 | 否 | 否 |

MySQL InnoDB 默认：**可重复读**。

### 30.4 MVCC

多版本并发控制：每行保存版本信息，读操作读快照，写操作创建新版本，减少读写锁冲突。

- 2NF：消除非主属性对主键的部分依赖。
- 3NF：消除非主属性对主键的传递依赖。
- 反范式：适当冗余，换查询性能。

NoSQL：

- Redis：KV/缓存/分布式锁/排行榜。
- MongoDB：文档。
- Elasticsearch：搜索。
- HBase/Cassandra：海量列存储。

Redis 常见：

# 第八部分：安全

## 36. XSS ⭐⭐⭐

三种：

- 存储型：恶意脚本存到数据库，所有访问者中招。
- 反射型：恶意脚本在 URL，服务端原样返回。
- DOM 型：前端把不可信数据插入 DOM。

防御：

- 输出转义（HTML/JS/URL）。
- 用 `textContent`，不用 `innerHTML` 拼用户输入。
- `DOMPurify` 清洗富文本。
- CSP（Content-Security-Policy）。
- Cookie `HttpOnly`。
- 输入校验。

```js
// 危险
el.innerHTML = `<p>${userInput}</p>`;

// 安全
el.textContent = userInput;
```

## 37. CSRF ⭐⭐⭐

攻击者诱导已登录用户向目标站点发请求。

防御：

- CSRF Token（表单/请求头）。
- Cookie `SameSite=Lax/Strict`。
- 校验 `Origin`/`Referer`。
- 关键操作二次验证。
- 不要把 token 放 URL。

## 38. 密码存储 ⭐⭐

- 不要明文/MD5/SHA1。
- 用 bcrypt/argon2/scrypt + 随机盐。
- 密码强度/限流/验证码。
- HTTPS 传输。

## 39. JWT ⭐⭐

```text
header.payload.signature
```

- payload 只是 Base64 编码，**不是加密**，不能放密码/密钥。
- 签名防篡改，不防泄露。
- 设置过期时间，配合 refresh token。
- 存储：HttpOnly Cookie 更安全；localStorage 方便但怕 XSS。

## 48. 面试答题模板

### 48.1 概念题

```text
是什么 → 原理/流程 → 优缺点/对比 → 项目里怎么用 → 边界
```

示例“TCP 三次握手”：

> TCP 是面向连接的协议。三次握手是客户端发 SYN，服务端回 SYN+ACK，客户端再回 ACK。目的是双方都确认自己的发送和接收能力正常，并同步初始序列号。两次不够，因为服务端无法确认客户端能收到自己的包；四次没必要。项目里我们一般不用直接处理，但排查网络问题时会用抓包看握手/重传。

### 48.2 算法题

```text
1. 复述题意 + 确认边界（空数组、重复、范围）
2. 说暴力解 + 复杂度
3. 说优化思路（哈希/双指针/DP/堆）
4. 写代码
5. 手动跑一个例子
6. 分析时间/空间复杂度
```

### 48.3 不会的题

> 这个点我了解得不深。我的理解是 `[相邻知识]`，如果是我的话会从 `[思路]` 入手。回去我会把 `[具体知识点]` 补一下。

## 50. 最后一句

- 画：进程/线程、TCP 握手、HTTP 缓存、B+ 树、事件循环。
