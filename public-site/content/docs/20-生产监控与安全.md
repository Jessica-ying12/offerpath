## 1. 监控体系

```text
错误监控：JS 异常、资源加载失败、接口失败、白屏、崩溃
性能监控：Web Vitals、首屏、接口耗时、FPS、内存
业务监控：曝光、点击、转化漏斗、留存
日志/告警：错误率、白屏率、接口失败率、告警通知
```

### 1.1 错误监控（Web）

```js
window.addEventListener('error', (event) => {
  // 资源加载失败也会触发，target 不是 window
  report({
    type: 'error',
    message: event.message,
    filename: event.filename,
    lineno: event.lineno,
    colno: event.colno,
    stack: event.error?.stack,
  });
});

window.addEventListener('unhandledrejection', (event) => {
  report({
    type: 'unhandledrejection',
    reason: String(event.reason),
    stack: event.reason?.stack,
  });
});
```

React 错误边界：

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  componentDidCatch(error, info) {
    report({ type: 'react', error, info });
  }

  render() {
    return this.state.hasError ? <Fallback /> : this.props.children;
  }
}
```

Sentry：

```js
import * as Sentry from '@sentry/react';

Sentry.init({
  dsn: 'https://xxx@sentry.io/xxx',
  environment: import.meta.env.MODE,
  release: 'app@1.2.3',
  tracesSampleRate: 0.1,
  integrations: [Sentry.browserTracingIntegration()],
});
```

### 1.2 sourcemap

- 生产构建生成 sourcemap。
- 上传到监控平台，不公开部署。
- 用 `release` 关联版本。
- hidden-source-map：生成但不引用。

### 1.3 RN 错误监控

```js
import * as Sentry from '@sentry/react-native';

Sentry.init({
  dsn: '...',
  tracesSampleRate: 0.1,
});

// 捕获 JS 异常
Sentry.captureException(error);
```

- JS 异常：ErrorBoundary + Sentry。
- 原生崩溃：Crashlytics/Sentry。
- 白屏：启动兜底 + 日志。
- 符号表：JS sourcemap + iOS dSYM + Android mapping。

### 1.4 小程序错误监控

```js
App({
  onError(err) {
    report({ type: 'app-error', err });
  },
  onUnhandledRejection(res) {
    report({ type: 'unhandledrejection', reason: res.reason });
  },
});
```

- 用 `wx.onError` / `App.onError`。
- 接口失败/性能/白屏上报。
- 版本/机型/基础库版本。

## 2. 性能监控

### 2.1 Web Vitals

```js
import { onLCP, onINP, onCLS, onTTFB } from 'web-vitals';

onLCP((metric) => report(metric));
onINP((metric) => report(metric));
onCLS((metric) => report(metric));
onTTFB((metric) => report(metric));
```

| 指标 | 含义 | 目标 |
|---|---|---|
| LCP | 最大内容绘制 | < 2.5s |
| INP | 交互到下一次绘制 | < 200ms |
| CLS | 累积布局偏移 | < 0.1 |
| TTFB | 首字节 | < 800ms |

### 2.2 自定义打点

```js
performance.mark('home-start');
// ...
performance.mark('home-end');
performance.measure('home', 'home-start', 'home-end');

const [measure] = performance.getEntriesByName('home');
report({ name: 'home', duration: measure.duration });
```

### 2.3 RN 性能

- 启动时间、首屏时间。
- FPS/JS 线程长任务。
- 内存/崩溃率。
- 接口耗时。
- 用 Performance Monitor/Profiler/Sentry。

### 2.4 小程序性能

- 启动耗时、首屏、setData 次数/耗时。
- 接口耗时、错误率。
- 开发者工具 Performance/Audit + 真机。

## 3. 埋点

### 3.1 事件模型

```ts
type TrackEvent = {
  event: string;        // 事件名
  userId?: string;
  page?: string;
  ts: number;
  props?: Record<string, unknown>;
};
```

常见事件：

- 曝光（exposure）：元素进入视口。
- 点击（click）。
- 页面浏览（page_view）。
- 业务转化（add_cart、order、pay）。
- 性能（lcp、api_time）。

### 3.2 上报队列

```js
const queue = [];
let timer = null;

function track(event) {
  queue.push({ ...event, ts: Date.now() });

  if (queue.length >= 10) flush();
  else if (!timer) timer = setTimeout(flush, 3000);
}

function flush() {
  if (queue.length === 0) return;

  const events = queue.splice(0, queue.length);
  const body = JSON.stringify({ events });

  if (navigator.sendBeacon) {
    navigator.sendBeacon('/api/track', body);
  } else {
    fetch('/api/track', { method: 'POST', body, keepalive: true });
  }
}
```

### 3.3 注意

- 曝光去重、节流。
- 失败重试/本地缓存。
- 隐私合规：不采集敏感信息。
- 埋点命名规范/文档。
- 采样率：高频事件按比例采样。

## 5. Web 安全

### 5.1 XSS

- 存储型、反射型、DOM 型。
- 防御：输出转义、`textContent`、DOMPurify、CSP、HttpOnly。

```js
// 危险
el.innerHTML = userInput;

// 安全
el.textContent = userInput;

// 富文本
el.innerHTML = DOMPurify.sanitize(userInput);
```

### 5.2 CSRF

- CSRF Token、SameSite Cookie、Origin/Referer 校验、二次验证。

### 5.3 CSP

```http
Content-Security-Policy:
  default-src 'self';
  script-src 'self' https://cdn.example.com;
  img-src 'self' https://cdn.example.com data:;
  connect-src 'self' https://api.example.com;
  frame-ancestors 'none';
```

- 禁止内联脚本（或 nonce/hash）。
- 限制第三方域名。
- 报告模式先观察再强制。

### 5.4 HTTPS / HSTS

- 全站 HTTPS。
- HSTS 强制 HTTPS。
- 不要 mixed content。
- 证书有效期/自动续期。

### 5.5 Token 存储

- HttpOnly Cookie：XSS 读不到，但要防 CSRF。
- localStorage：方便，但 XSS 可读。
- 移动端：Keychain/Keystore/SecureStore。
- 短过期 + refresh token + 撤销。

### 5.6 依赖与密钥

- `npm audit` / Dependabot。
- 锁版本/lockfile。
- 不要提交 `.env`/密钥/证书。
- 最小权限/定期轮换。
- 供应链攻击：校验包名/来源。

### 5.7 WebView 安全

- 只加载可信页面。
- 关闭调试/文件访问。
- 不忽略 SSL 错误。
- JSBridge 方法白名单/来源校验。
- 不通过 URL 传敏感信息。

### 5.8 小程序安全

- 请求域名白名单/HTTPS。
- 不把 secret 放前端。
- 支付/金额后端校验。
- 隐私协议/授权最小化。
- 防薅羊毛：风控/限流/签名。

## 6. 隐私与合规

- 最小必要原则：只采集需要的。
- 明示同意：隐私政策/授权弹窗。
- 敏感信息脱敏：手机号/身份证/地址。
- 数据加密/访问控制。
- 日志/埋点不采集密码/token。
- 遵守《个人信息保护法》/GDPR 等。

## 7. 面试高频

### Q1：前端怎么做错误监控？ ⭐⭐⭐

**答：** 监听 `window.onerror`/`unhandledrejection`，React 用 ErrorBoundary，资源加载失败单独处理；上报错误栈、URL、版本、设备；生产 sourcemap 还原；接 Sentry/自建平台。

### Q2：sourcemap 怎么处理？ ⭐⭐

**答：** 生产生成但不上传到公开 CDN，上传到监控平台；用 release 关联版本；hidden-source-map 只保留映射文件。

### Q3：Web Vitals 有哪些？ ⭐⭐⭐

**答：** LCP、INP、CLS、TTFB；LCP 衡量首屏，INP 衡量交互，CLS 衡量布局稳定性；FID 已被 INP 取代。

### Q4：RN/小程序怎么监控？ ⭐⭐

**答：** RN 用 Sentry/Crashlytics + ErrorBoundary + 原生日志 + sourcemap/dSYM/mapping；小程序用 App.onError/onUnhandledRejection + 接口/性能上报 + 版本/机型维度。

### Q5：埋点怎么设计？ ⭐⭐

**答：** 统一事件模型（event/user/page/ts/props），曝光/点击/页面/转化；队列批量上报，sendBeacon/keepalive；失败重试/本地缓存；去重/采样/隐私合规。

### Q6：告警怎么设计？ ⭐⭐

**答：** 指标 + 阈值 + 影响面 + 负责人 + 预案；错误率/白屏率/接口失败率/崩溃率；告警要可执行，避免噪音。

### Q7：XSS 怎么防？ ⭐⭐⭐

**答：** 输出转义、textContent、DOMPurify、CSP、HttpOnly Cookie；不要用 innerHTML 拼用户输入；富文本白名单。

### Q8：CSRF 怎么防？ ⭐⭐⭐

**答：** CSRF Token、SameSite Cookie、Origin/Referer 校验、关键操作二次验证；不要把 token 放 URL。

### Q9：CSP 怎么配？ ⭐⭐

**答：** 限制 default-src/script-src/connect-src/frame-ancestors；禁止内联脚本或使用 nonce/hash；先 report-only 观察再强制。

### Q10：token 放哪？ ⭐⭐⭐

**答：** Web 优先 HttpOnly Cookie + CSRF 防护；localStorage 方便但怕 XSS；移动端用 Keychain/Keystore/SecureStore；短过期 + refresh。

### Q11：怎么防依赖/供应链风险？ ⭐⭐

**答：** npm audit/Dependabot、lockfile、锁版本、校验来源、最小权限、定期升级；不要随便装未知包。

### Q12：WebView 安全注意什么？ ⭐⭐

**答：** 只加载可信页面、HTTPS、关闭调试/文件访问、不忽略 SSL 错误、JSBridge 白名单/来源校验、不通过 URL 传敏感信息。

### Q13：线上故障怎么处理？ ⭐⭐

**答：** 先止血（回滚/开关/降级/限流），再定位（日志/监控/请求 ID/版本/机型），修复根因，最后复盘/补监控/补测试。

### Q14：隐私合规怎么做？ ⭐⭐

**答：** 最小必要、明示同意、脱敏、加密、访问控制、日志/埋点不采集敏感信息；遵守个保法/GDPR。
