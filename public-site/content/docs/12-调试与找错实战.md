# 12 · 调试与找错实战

> 目标：给你一段有 bug 的代码，你能在 5 分钟内说出“错在哪、为什么、怎么修、怎么防”。
>
> 用法：
> 1. 先只看题目和代码，自己找 3 分钟。
> 2. 再看折叠的答案。
> 3. 把错题记到错题本，第二天重做。
>
> 说明：答案里的“修复”不只给最终代码，还给根因和同类题，方便你举一反三。

---

## 1. 为什么你会“看不出 bug”

新手常见的三个问题：

1. **只看代码，不看运行结果**：脑内推演和实际执行不一致。
2. **只看报错最后一行**：没看错误类型、调用栈、自己的文件名。
3. **改到能跑就停**：没搞清根因，换个场景又错。

调试的核心不是“盯着代码看”，而是：

```text
提出假设 → 设计实验 → 观察结果 → 缩小范围 → 修复根因
```

## 2. 调试八步法

### 第 1 步：稳定复现

- 什么操作？什么输入？什么环境？
- 每次都能复现吗？
- 线上还是本地？iOS 还是 Android？哪个机型/浏览器？

不能复现，就先加日志/埋点，别急着改代码。

### 第 2 步：读完整报错

```text
TypeError: Cannot read properties of undefined (reading 'map')
    at ProductList (ProductList.jsx:12:24)
    at renderWithHooks (...)
```

- **错误类型**：TypeError。
- **错误信息**：读取 undefined 的 `map`。
- **位置**：`ProductList.jsx:12`。
- **调用栈**：从下往上看，找到你自己的文件。

### 第 3 步：打印关键变量

在报错行之前打印：

```js
console.log('list =', list, 'type =', typeof list, 'isArray =', Array.isArray(list));
```

不要只打印 `list`，要打印类型、长度、结构。

### 第 4 步：二分定位

代码很长时，不要从头看到尾：

- 注释掉一半，看 bug 是否还在。
- 在中间加 `return` / `console.log`。
- 把可疑逻辑抽成最小函数单独跑。

### 第 5 步：检查异步时序

很多 bug 不是“值错了”，而是“值还没回来”：

```js
console.log('before', list);
await load();
console.log('after', list);
```

检查：

- 有没有漏 `await`？
- `forEach` 里的 async 有没有被等？
- 请求有没有竞态？
- 组件卸载后有没有 setState？

### 第 6 步：检查引用和可变性

- 是不是直接改了 state/对象？
- 是不是浅拷贝了嵌套对象？
- 是不是多个地方共享同一个数组/对象？
- 是不是 `sort/splice/reverse` 改了原数组？

### 第 7 步：检查环境和构建

- 本地好的，线上坏：环境变量/接口地址/缓存/构建产物。
- 只有 iOS 坏：安全区/键盘/日期解析/正则。
- 只有 Android 坏：明文 HTTP/权限/机型。
- 只有小程序坏：域名白名单/分包/setData。

### 第 8 步：修根因 + 回归

- 不要用 `try {} catch {}` 吞掉错误。
- 不要用 `!important` 压样式。
- 不要删掉“看起来没用”的代码。
- 修完跑：正常路径 + 边界 + 相关功能。
- 写一条回归用例（单测/手测步骤）。

## 3. 读报错速查

| 报错 | 大概率原因 | 先看哪里 |
|---|---|---|
| `Cannot read properties of undefined (reading 'x')` | 对象/数组还没加载 | 数据来源、loading 判断 |
| `x is not a function` | 类型不对/导入错/拼写错 | `typeof x`、import/export |
| `Unexpected token '<'` | 接口返回 HTML/JSX 没编译 | Network 响应、Babel 配置 |
| `Unexpected end of JSON input` | 响应为空/不是 JSON | `res.text()` |
| `Assignment to constant variable` | 给 const 重新赋值 | 改 let 或改内容 |
| `Maximum call stack size exceeded` | 递归没终止/循环引用 | 终止条件、WeakMap |
| `Uncaught (in promise)` | Promise 没 catch | 加 catch |
| `Each child in a list should have a unique key` | 列表 key 缺失/重复 | key |
| `Rendered more hooks than during the previous render` | 条件/循环里用 Hook | Hook 移到顶层 |
| `Too many re-renders` | render 里 setState/effect 死循环 | setState 位置、依赖 |
| `Objects are not valid as a React child` | 直接渲染对象 | 取字段/JSON.stringify |
| `Unable to resolve module`（RN） | 依赖/路径错 | 安装依赖、相对路径 |
| `Network request failed`（RN） | 网络/HTTP/ATS | HTTPS、权限 |
| `request:fail url not in domain list` | 小程序域名没配 | 公众平台域名配置 |
| `Module not found`（Webpack） | 路径/依赖/alias | 路径、`npm i` |
| `RenderFlex overflowed`（Flutter） | Row/Column 超约束 | Expanded/Flexible |

### 4.1 JavaScript 基础

#### 题 1：为什么输出 3 3 3？

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

**期望：** 0 1 2
**实际：** 3 3 3
**任务：** 找出原因并修复。

<details>
<summary>答案</summary>

**根因：** `var` 是函数作用域，三个回调共享同一个 `i`；循环结束时 `i = 3`。

**修复 1：用 `let`**

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

**修复 2：IIFE 保存每次的值**

```js
for (var i = 0; i < 3; i++) {
  (function (value) {
    setTimeout(() => console.log(value), 0);
  })(i);
}
```

**延伸：** 这就是闭包 + 事件循环的经典题。`let` 每次迭代创建新的块级绑定。

</details>

#### 题 2：为什么输出 NaN？

```js
const counter = {
  count: 0,
  start() {
    setInterval(function () {
      this.count++;
      console.log(this.count);
    }, 1000);
  },
};

counter.start();
```

**期望：** 1 2 3
**实际：** NaN
**任务：** 解释 `this` 指向，并修复。

<details>
<summary>答案</summary>

**根因：** `setInterval` 的普通函数回调里，`this` 不是 `counter`。严格模式下是 `undefined`，非严格浏览器里是 `window`。`window.count` 是 undefined，`undefined++` 变成 NaN。

**修复 1：箭头函数**

```js
start() {
  setInterval(() => {
    this.count++;
    console.log(this.count);
  }, 1000);
}
```

**修复 2：bind**

```js
start() {
  setInterval(function () {
    this.count++;
    console.log(this.count);
  }.bind(this), 1000);
}
```

**延伸：** 对象方法、回调、`setTimeout`、事件监听都是 `this` 丢失的高发区。

</details>

#### 题 3：为什么原对象被改了？

```js
const state = {
  user: { name: 'Tom' },
  list: [1, 2],
};

const next = { ...state };
next.user.name = 'Jerry';

console.log(state.user.name); // ?
```

**期望：** Tom
**实际：** Jerry
**任务：** 解释并修复。

<details>
<summary>答案</summary>

**根因：** 展开运算符是浅拷贝，`next.user` 和 `state.user` 指向同一个对象。

**修复：**

```js
const next = {
  ...state,
  user: { ...state.user, name: 'Jerry' },
};
```

**延伸：** React/RN 的 state 更新必须逐层创建新对象；深拷贝可以用 `structuredClone` 或递归。

</details>

#### 题 4：为什么排序结果不对？

```js
const nums = [10, 2, 1, 30];
nums.sort();
console.log(nums);
```

**期望：** [1, 2, 10, 30]
**实际：** [1, 10, 2, 30]
**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `sort()` 默认把元素转成字符串，按字典序比较。

**修复：**

```js
nums.sort((a, b) => a - b); // 升序
```

**延伸：** `sort` 会修改原数组；需要新数组用 `[...nums].sort()` 或 `toSorted()`。

</details>

#### 题 5：为什么 `map(parseInt)` 得到 NaN？

```js
const result = ['1', '2', '3'].map(parseInt);
console.log(result);
```

**期望：** [1, 2, 3]
**实际：** [1, NaN, NaN]
**任务：** 解释。

<details>
<summary>答案</summary>

**根因：** `map` 给回调传 `(value, index, array)`，`parseInt` 的第二个参数是**进制**：

```js
parseInt('1', 0); // 1（0 当作 10 进制）
parseInt('2', 1); // NaN（进制 1 非法）
parseInt('3', 2); // NaN（二进制里没有 3）
```

**修复：**

```js
['1', '2', '3'].map(Number);
// 或
['1', '2', '3'].map((s) => parseInt(s, 10));
```

**延伸：** 不要把有多个参数的内置函数直接当回调传。

</details>

#### 题 6：为什么 0 被判断成空？

```js
function isEmpty(value) {
  return value == '';
}

console.log(isEmpty(0));   // ?
console.log(isEmpty(''));  // ?
```

**期望：** false, true
**实际：** true, true
**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `==` 会做类型转换，`0 == ''` 为 true。

**修复：**

```js
function isEmpty(value) {
  return value === '';
}
```

**延伸：** 业务代码统一用 `===`；只有判断 null/undefined 时可以用 `x == null`。

</details>

#### 题 7：为什么永远判断不出 NaN？

```js
function isInvalid(score) {
  return score === NaN;
}

console.log(isInvalid(NaN)); // false
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `NaN` 不等于任何值，包括它自己。

**修复：**

```js
function isInvalid(score) {
  return Number.isNaN(score);
}
```

**延伸：** `Object.is(NaN, NaN)` 也是 true；全局 `isNaN('abc')` 会先转数字，容易误判。

</details>

#### 题 8：为什么 0.1 + 0.2 不等于 0.3？

```js
console.log(0.1 + 0.2 === 0.3); // false
```

**任务：** 解释并给出两种修复。

<details>
<summary>答案</summary>

**根因：** IEEE 754 双精度浮点数无法精确表示 0.1/0.2，相加后有微小误差。

**修复 1：误差范围**

```js
function isEqual(a, b, epsilon = 1e-9) {
  return Math.abs(a - b) < epsilon;
}
```

**修复 2：金额用整数分**

```js
const total = (10 + 20) / 100; // 0.3
```

**延伸：** 金额不要用浮点数；可以用整数分或 `decimal.js`。

</details>

#### 题 9：为什么三个对象都变了？

```js
const list = new Array(3).fill({});
list[0].name = 'Tom';
console.log(list);
```

**期望：** 只有第一个有 name
**实际：** 三个都有
**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `fill({})` 把**同一个对象引用**填了三次。

**修复：**

```js
const list = Array.from({ length: 3 }, () => ({}));
list[0].name = 'Tom';
```

**延伸：** `new Array(3).fill([])` 也是同一个坑。

</details>

#### 题 10：为什么拷贝后 Date 和函数没了？

```js
const source = {
  date: new Date(),
  fn: () => console.log('hi'),
  value: undefined,
};

const copy = JSON.parse(JSON.stringify(source));
console.log(copy);
```

**任务：** 指出丢失/变化，并给出替代方案。

<details>
<summary>答案</summary>

**根因：** JSON 序列化只支持 JSON 类型：

- `Date` 变成字符串。
- 函数、`undefined`、`Symbol` 丢失。
- `Map/Set` 变空对象。
- 循环引用报错。

**修复：**

```js
const copy = structuredClone(source);
```

注意 `structuredClone` 也不支持函数/DOM 节点。需要保留函数时，手写递归或按业务处理。

</details>

### 4.2 异步

#### 题 11：为什么 results 是空的？

```js
async function loadAll(ids) {
  const results = [];

  ids.forEach(async (id) => {
    const data = await fetchItem(id);
    results.push(data);
  });

  return results;
}
```

**期望：** 所有结果
**实际：** `[]`
**任务：** 修复，并保证顺序。

<details>
<summary>答案</summary>

**根因：** `forEach` 不会等待 async 回调；函数在请求完成前就返回了。

**修复 1：Promise.all（并行，保持顺序）**

```js
async function loadAll(ids) {
  return Promise.all(ids.map((id) => fetchItem(id)));
}
```

**修复 2：for...of（串行）**

```js
async function loadAll(ids) {
  const results = [];
  for (const id of ids) {
    results.push(await fetchItem(id));
  }
  return results;
}
```

**延伸：** `map` 里的 async 也一样，要 `Promise.all`。

</details>

async function getUser() {

}

<summary>答案</summary>

#### 题 13：为什么 try/catch 没捕获到？

```js
try {
  setTimeout(() => {
    throw new Error('boom');
  }, 0);
} catch (err) {
  console.log('caught');
}
```

**期望：** caught
**实际：** 未捕获，控制台报错
**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `try/catch` 只能捕获当前同步执行栈里的错误。回调在 setTimeout 里执行时，已经离开了 try 的作用域。

**修复：**

```js
setTimeout(() => {
  try {
    throw new Error('boom');
  } catch (err) {
    console.log('caught', err);
  }
}, 0);
```

**延伸：** Promise 的错误用 `.catch`；全局兜底用 `window.onerror` / `unhandledrejection`。

</details>

#### 题 14：为什么一个失败全部失败？

```js
async function loadAll(urls) {
  const results = await Promise.all(urls.map(fetchJson));
  return results;
}
```

**需求：** 某个接口失败时，其他成功的结果也要保留。

<details>
<summary>答案</summary>

**根因：** `Promise.all` 是 fail-fast：任何一个 reject，整体立即 reject。

**修复：**

```js
async function loadAll(urls) {
  const settled = await Promise.allSettled(urls.map(fetchJson));

  return settled.map((item) =>
    item.status === 'fulfilled'
      ? { ok: true, data: item.value }
      : { ok: false, error: item.reason }
  );
}
```

**延伸：** `all` 全部成功才成功；`allSettled` 等全部结束；`race` 第一个结束；`any` 第一个成功。

</details>

#### 题 15：为什么搜索结果显示的是旧关键词？

```js
let keyword = '';

input.addEventListener('input', async (e) => {
  keyword = e.target.value;
  const data = await search(keyword);
  render(data);
});
```

**现象：** 快速输入时，先发的请求后回来，覆盖了新结果。
**任务：** 修复竞态。

<details>
<summary>答案</summary>

**根因：** 请求完成顺序不等于发起顺序。

**修复 1：AbortController**

```js
let controller = null;

input.addEventListener('input', async (e) => {
  if (controller) controller.abort();
  controller = new AbortController();

  const keyword = e.target.value;

  try {
    const data = await search(keyword, controller.signal);
    render(data);
  } catch (err) {
    if (err.name !== 'AbortError') throw err;
  }
});
```

**修复 2：请求序号**

```js
let requestId = 0;

input.addEventListener('input', async (e) => {
  const currentId = ++requestId;
  const data = await search(e.target.value);
  if (currentId !== requestId) return; // 不是最新请求，丢弃
  render(data);
});
```

**延伸：** 搜索框还要加防抖，减少请求量。

</details>

#### 题 16：为什么 data 是 undefined？

```js
function load() {
  let data;
  fetch('/api/data')
    .then((res) => res.json())
    .then((result) => {
      data = result;
    });
  return data;
}
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `fetch` 是异步的，`return data` 在请求完成前执行。

**修复：**

```js
async function load() {
  const res = await fetch('/api/data');
  return res.json();
}
```

或者返回 Promise：

```js
function load() {
  return fetch('/api/data').then((res) => res.json());
}
```

**延伸：** 异步函数的返回值一定包在 Promise 里，调用方要 `await` 或 `.then`。

</details>

#### 题 17：为什么会报 Uncaught (in promise)？

```js
function load() {
  fetch('/api/data').then((res) => res.json());
}

load();
```

**任务：** 修复错误处理。

<details>
<summary>答案</summary>

**根因：** Promise 链没有 `.catch`，网络错误/JSON 解析错误变成未处理拒绝。

**修复：**

```js
async function load() {
  try {
    const res = await fetch('/api/data');
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (err) {
    console.error('加载失败', err);
    throw err; // 让调用方也能处理
  }
}
```

**延伸：** 不要用空的 `catch {}` 吞错；至少打日志/上报。

</details>

### 4.3 React

#### 题 18：为什么列表不更新？

```jsx
function App() {
  const [todos, setTodos] = useState([]);

  function addTodo(title) {
    todos.push({ id: Date.now(), title });
    setTodos(todos);
  }

  return <TodoList todos={todos} />;
}
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** 直接修改了 state 数组，引用没变，React 可能跳过更新。

**修复：**

```jsx
function addTodo(title) {
  setTodos((prev) => [
    ...prev,
    { id: Date.now(), title },
  ]);
}
```

**延伸：** React 不可变更新：新增用展开/concat，删除用 filter，修改用 map + 展开。

</details>

#### 题 19：为什么删除第一项后输入框内容串了？

```jsx
{todos.map((todo, index) => (
  <TodoItem key={index} todo={todo} />
))}
```

**任务：** 解释并修复。

<details>
<summary>答案</summary>

**根因：** 用 index 做 key，删除/排序后 React 会复用错误的节点和组件状态。

**修复：**

```jsx
{todos.map((todo) => (
  <TodoItem key={todo.id} todo={todo} />
))}
```

**延伸：** key 要稳定、唯一、可预测；不要用随机数。

</details>

#### 题 20：为什么定时器里的 count 一直是 0？

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    setCount(count + 1);
  }, 1000);

  return () => clearInterval(timer);
}, []);
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** 空依赖数组让 effect 只执行一次，闭包捕获的是首次渲染的 `count = 0`。

**修复 1：函数式更新**

```jsx
setCount((prev) => prev + 1);
```

**修复 2：把 count 放进依赖（会重建定时器）**

```jsx
useEffect(() => {
  const timer = setInterval(() => setCount(count + 1), 1000);
  return () => clearInterval(timer);
}, [count]);
```

**延伸：** 定时器/事件监听里读取 state，优先用函数式更新或 ref。

</details>

#### 题 21：为什么页面无限重渲染？

```jsx
function App() {
  const [count, setCount] = useState(0);
  setCount(count + 1);
  return <div>{count}</div>;
}
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** 在 render 阶段调用 setState，触发下一次 render，再 setState，形成死循环。

**修复：**

```jsx
function App() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount((c) => c + 1)}>
      {count}
    </button>
  );
}
```

**延伸：** 初始化状态用 `useState(initial)`，不要在 render 里 setState。

</details>

#### 题 22：为什么 Hook 报错？

```jsx
function App({ isVip }) {
  if (isVip) {
    const [level, setLevel] = useState(1);
  }

  return <div>...</div>;
}
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** Hook 只能在组件顶层调用，不能放在条件/循环/嵌套函数里。React 靠调用顺序匹配 state。

**修复：**

```jsx
function App({ isVip }) {
  const [level, setLevel] = useState(1);

  if (isVip) {
    // 使用 level
  }

  return <div>...</div>;
}
```

</details>

#### 题 23：为什么组件卸载后还报 setState？

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    setCount((c) => c + 1);
  }, 1000);
}, []);
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** 组件卸载后定时器还在跑，继续 setState。

**修复：**

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    setCount((c) => c + 1);
  }, 1000);

  return () => clearInterval(timer);
}, []);
```

**延伸：** 事件监听、订阅、WebSocket、请求都要在清理函数里取消。

</details>

#### 题 24：为什么 useEffect 一直重复执行？

```jsx
useEffect(() => {
  load({ id });
}, [{ id }]);
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** 依赖数组里放了一个每次渲染都新建的对象 `{ id }`，浅比较永远不相等。

**修复：**

```jsx
useEffect(() => {
  load({ id });
}, [id]);
```

**延伸：** 依赖数组放原始值；如果必须放对象，用 `useMemo` 稳定引用。

</details>

#### 题 25：为什么 useEffect 里直接写 async 会警告？

```jsx
useEffect(async () => {
  const data = await fetchData();
  setData(data);
}, []);
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `useEffect` 的回调必须返回清理函数或 undefined，不能返回 Promise。

**修复：**

```jsx
useEffect(() => {
  let cancelled = false;

  async function load() {
    const data = await fetchData();
    if (!cancelled) setData(data);
  }

  load();

  return () => {
    cancelled = true;
  };
}, []);
```

</details>

### 4.4 React Native

#### 题 26：为什么长列表很卡？

```jsx
<ScrollView>
  {posts.map((post) => (
    <PostCard key={post.id} post={post} />
  ))}
</ScrollView>
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** ScrollView 会一次性渲染所有子项，1000 条就创建 1000 个原生视图。

**修复：**

```jsx
<FlatList
  data={posts}
  keyExtractor={(item) => String(item.id)}
  renderItem={({ item }) => <PostCard post={item} />}
  initialNumToRender={10}
  maxToRenderPerBatch={10}
  windowSize={7}
/>
```

**延伸：** 固定行高加 `getItemLayout`；列表项用 `memo`。

</details>

#### 题 27：为什么 FlatList 报警告且滚动卡？

```jsx
<FlatList
  data={posts}
  renderItem={({ item }) => (
    <PostCard
      post={item}
      onPress={() => navigation.navigate('Detail', { id: item.id })}
    />
  )}
/>
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：**

1. 没有 `keyExtractor`，FlatList 默认用 index 做 key。
2. `renderItem` 每次渲染新建箭头函数，`PostCard` 容易重渲染。

**修复：**

```jsx
const renderItem = useCallback(
  ({ item }) => <PostCard post={item} onPress={openDetail} />,
  [openDetail]
);

<FlatList
  data={posts}
  keyExtractor={(item) => String(item.id)}
  renderItem={renderItem}
/>
```

`PostCard` 用 `memo` 包裹，`openDetail` 用 `useCallback` 稳定引用。

</details>

#### 题 28：为什么接口失败时页面一直白屏？

```jsx
useEffect(() => {
  fetch(API)
    .then((res) => res.json())
    .then(setPosts);
}, []);
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** 没有处理 HTTP 错误、网络错误、loading 状态；失败时 `posts` 仍是空，页面没有任何提示。

**修复：**

```jsx
useEffect(() => {
  let cancelled = false;

  async function load() {
    try {
      setLoading(true);
      setError('');
      const res = await fetch(API);
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const data = await res.json();
      if (!cancelled) setPosts(data);
    } catch (err) {
      if (!cancelled) setError(err.message);
    } finally {
      if (!cancelled) setLoading(false);
    }
  }

  load();
  return () => { cancelled = true; };
}, []);
```

**延伸：** Android 9+ 默认禁止明文 HTTP；要 HTTPS 或配置 `usesCleartextTraffic`。

</details>

### 4.5 微信小程序

#### 题 29：为什么列表渲染不出来？

```js
Page({
  data: { list: [] },

  addItem(item) {
    this.setData({
      list: this.data.list.push(item),
    });
  },
});
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `push` 返回的是新长度（number），`list` 被设置成了数字，WXML 无法遍历。

**修复：**

```js
addItem(item) {
  this.setData({
    list: [...this.data.list, item],
  });
}
```

或路径更新：

```js
this.setData({
  [`list[${this.data.list.length}]`]: item,
});
```

**延伸：** 不要直接改 `this.data`；用 `setData` 传新数组/路径。

</details>

#### 题 30：为什么点文字拿不到 id？

```xml
<view class="item" bindtap="onDelete" data-id="{{item.id}}">
  <text>删除</text>
</view>
```

```js
onDelete(e) {
  const id = e.target.dataset.id;
  console.log(id); // undefined
}
```

**任务：** 修复。

<details>
<summary>答案</summary>

**根因：** `e.target` 是实际点击的最深节点（`text`），它没有 `data-id`；`e.currentTarget` 才是绑定事件的 `view`。

**修复：**

```js
onDelete(e) {
  const id = e.currentTarget.dataset.id;
  console.log(id);
}
```

**延伸：** 事件委托里也常用 `closest`/`currentTarget` 找绑定元素。

</details>

#### 题 33：为什么 z-index 再大也盖不住？

```css
.parent {
  transform: translateZ(0);
}

.child {
  position: absolute;
  z-index: 9999;
}
```

**任务：** 解释并修复。

<details>
<summary>答案</summary>

**根因：** `transform` 让 `.parent` 创建了新的层叠上下文，`.child` 的 `z-index` 只在 `.parent` 内部比较，跳不出去。

**修复：**

- 把浮层挂到 `body`（React Portal / Vue Teleport）。
- 或移除父级的 `transform`/`opacity`/`filter`。
- 或调整 DOM 层级，让浮层和要覆盖的元素在同一层叠上下文。

**延伸：** `z-index` 只对定位元素/flex/grid 子项生效，且只在同一层叠上下文内比较。

</details>

#### 题 34：为什么接口在浏览器里报 CORS？

```js
fetch('https://api.example.com/data')
  .then((res) => res.json())
  .then(console.log);
```

**现象：** `Access to fetch at ... has been blocked by CORS policy`
**任务：** 说明这是不是前端代码的 bug，并给出三种解决。

<details>
<summary>答案</summary>

**根因：** 浏览器同源策略。不是 JS 语法错误，是服务端没有返回允许跨域的响应头。

**解决：**

1. 后端配置 CORS：`Access-Control-Allow-Origin`、`Allow-Methods`、`Allow-Headers`，带 cookie 还要 `Allow-Credentials`。
2. 开发环境用 Vite/Webpack 代理，把请求转发到同源。
3. 生产环境同域部署或 Nginx 反向代理。
4. JSONP 只支持 GET，已很少用。

**延伸：** 简单请求不会预检；带自定义头/非简单方法会先发 `OPTIONS` 预检。

</details>

## 5. 线上问题排查流程

```text
1. 确认影响面：哪些用户/机型/版本/地区
2. 看监控：错误率、接口失败率、白屏率、崩溃率
3. 看日志：错误栈、用户 ID、请求 ID、时间
4. 复现：本地/测试环境/真机
5. 定位：二分、开关、灰度、回滚
6. 修复：根因 + 兜底
7. 回归：正常/边界/相关功能
8. 复盘：5 Why、改进项、监控
```

### 5.1 常见线上问题

| 现象 | 可能原因 | 先查 |
|---|---|---|
| 白屏 | JS 报错、bundle 加载失败、接口挂了 | Sentry、Network、CDN |
| 页面错乱 | 缓存了旧 HTML/旧 JS | index.html 缓存、hash |
| 只有 iOS 坏 | 日期解析、安全区、键盘 | 真机日志 |
| 只有 Android 坏 | 明文 HTTP、权限、机型 | logcat、网络配置 |
| 小程序打不开 | 域名/分包/审核版本 | 开发者工具、体验版 |
| RN 红屏 | JS 异常、原生模块、bundle | Metro、Dev Menu |
