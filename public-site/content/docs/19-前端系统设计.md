# 19 · 前端系统设计

> 目标：面试官说“设计一个电商 App / 信息流 / 聊天 / 中后台”，你能按“需求 → 架构 → 数据 → 性能 → 监控 → 取舍”讲清楚。
>
> 标记：⭐⭐⭐ 必须会｜⭐⭐ 要理解｜⭐ 了解即可

---

## 1. 系统设计面试的 7 步

```text
1. 澄清需求：用户是谁？核心功能？端？规模？
2. 非功能要求：性能、可用性、安全、成本、工期
3. 画页面/模块：页面地图、组件树
4. 定接口：API、数据结构、状态码
5. 定架构：分层、状态、路由、缓存、跨端
6. 深入 1-2 个点：性能/一致性/权限/离线
7. 说取舍：为什么这么选，替代方案是什么
```

**不要一上来就写代码/选框架。** 先确认边界。

---

## 2. 需求与约束

### 2.1 功能需求

- 用户能做什么？
- 核心路径是什么？（浏览 → 搜索 → 详情 → 下单 → 支付）
- 哪些是 MVP，哪些是后续？

### 2.2 非功能需求

| 维度 | 问题 |
|---|---|
| 性能 | 首屏、列表、弱网、低端机 |
| 可用性 | 降级、重试、离线、灰度 |
| 安全 | 登录、支付、权限、隐私 |
| 规模 | 用户量、QPS、数据量 |
| 成本 | 人力、服务器、包体积 |
| 工期 | 先上线还是先完美 |

## 3. 前端架构分层

```text
┌─────────────────────────────┐
│ 页面/路由层（Pages/Router）    │
├─────────────────────────────┤
│ 组件层（Components/Design System）│
├─────────────────────────────┤
│ 状态层（Server/Client State）  │
├─────────────────────────────┤
│ 服务层（API/Storage/Auth）     │
├─────────────────────────────┤
│ 基础层（Request/Utils/Config） │
└─────────────────────────────┘
```

原则：

- 页面只做组合，不写复杂业务。
- 组件可复用、可测试。
- 服务端数据与 UI 状态分开。
- 请求/存储/鉴权统一封装。
- 配置/环境变量集中管理。

---

## 4. 组件库 / 设计系统

### 4.1 结构

```text
packages/ui/
├── src/
│   ├── Button/
│   ├── Input/
│   ├── Modal/
│   ├── theme/
│   └── index.ts
├── package.json
└── README.md
```

### 4.2 设计原则

- 原子化：基础组件 → 业务组件 → 页面。
- 受控/非受控都支持。
- 主题用 CSS 变量/ThemeProvider。
- 无障碍：role/label/键盘。
- 文档 + Storybook + 视觉回归。
- 版本化/变更日志。

### 4.3 跨端组件

- H5/RN 共享业务逻辑，UI 分开。
- 小程序组件用 WXML/WXSS 单独实现。
- 用 design tokens 统一颜色/间距/字号。

## 5. Monorepo

```text
repo/
├── apps/
│   ├── web/
│   ├── admin/
│   └── mobile/
├── packages/
│   ├── ui/
│   ├── utils/
│   ├── api/
│   └── config/
├── pnpm-workspace.yaml
└── turbo.json
```

优点：

- 代码共享、统一依赖/规范。
- 原子提交/联调方便。
- 统一 CI/发布。

缺点：

- 仓库大、构建慢。
- 权限/版本/发布复杂。
- 需要缓存/任务编排（Turborepo/Nx）。

`pnpm-workspace.yaml`：

```yaml
packages:
  - 'apps/*'
  - 'packages/*'
```

## 6. 微前端

适用：

- 多个团队独立开发/发布。
- 老系统逐步迁移。
- 不同技术栈共存。

方案：

- qiankun（基于 single-spa）。
- Module Federation（Webpack 5）。
- iframe（隔离好但体验/通信差）。

代价：

- 路由/样式/JS 隔离。
- 公共依赖重复/版本冲突。
- 通信/鉴权/监控复杂。
- 性能/调试成本。

**建议：** 小团队/单业务不要上微前端；先模块化/Monorepo。

## 7. SSR / SSG / BFF

| 方案 | 首屏 | SEO | 成本 |
|---|---|---|---|
| CSR | 慢 | 差 | 低 |
| SSR | 快 | 好 | 中/高（服务器） |
| SSG | 最快 | 好 | 低（构建） |
| BFF | 聚合接口 | — | 中 |

BFF（Backend for Frontend）：

- 为前端聚合/裁剪接口。
- 处理鉴权/缓存/降级。
- 可以用 Node/GraphQL。

SSR 注意：

- 浏览器 API 不能在服务端用。
- 数据预取/hydration 一致。
- 缓存/降级/服务器成本。

## 8. 状态管理

分两类：

- **服务端状态**：接口数据、缓存、分页、请求状态 → TanStack Query/SWR。
- **客户端状态**：登录用户、主题、购物车、UI 状态 → Context/Zustand/Redux。

原则：

- 状态放最近需要它的地方。
- 能算出来的不要存。
- 服务端数据不要复制到全局 store。
- 用 selectors/拆分 Context 减少重渲染。

## 9. 性能、监控、安全

### 9.1 性能

- 首屏：代码分割、图片、缓存、SSR、骨架。
- 列表：虚拟滚动、分页、图片懒加载。
- 交互：防抖/节流、乐观更新、减少重渲染。
- 弱网：缓存、重试、离线包。

### 9.2 监控

- 错误：Sentry/自建、sourcemap。
- 性能：Web Vitals、RUM、自定义埋点。
- 业务：转化漏斗、曝光/点击。
- 告警：错误率、白屏率、接口失败率。

### 9.3 安全

- 登录/token 存储、HTTPS。
- 权限校验（前端 + 后端）。
- 支付/金额以后端为准。
- XSS/CSRF/注入防护。
- 隐私合规。

## 10. 案例：电商 App

### 10.1 页面

```text
首页 → 分类/搜索 → 商品列表 → 商品详情 → 购物车 → 确认订单 → 支付 → 订单
```

### 10.2 接口

```text
GET  /home
GET  /goods?keyword=&page=
GET  /goods/:id
POST /cart/items
PATCH /cart/items/:id
POST /orders
POST /payments
GET  /orders
```

### 10.3 状态

- 服务端：商品/订单/购物车（TanStack Query 缓存）。
- 客户端：登录用户、主题、地址选择。
- 本地：搜索历史、最近浏览。

### 10.4 性能

- 图片 CDN/缩略图/懒加载。
- 列表虚拟滚动/分页。
- 详情预加载/骨架屏。
- 购物车乐观更新。

### 10.5 关键取舍

- 购物车放服务端还是本地？登录后同步，未登录本地。
- 支付结果以服务端回调为准。
- 多端（App/小程序/H5）共享 API 和业务逻辑，UI 分开。

## 14. 面试高频

### Q1：系统设计怎么开头？ ⭐⭐⭐

**答：** 先澄清需求和非功能约束，再画页面/模块、定接口、定架构，最后深入 1-2 个点和取舍。不要一上来选框架。

### Q2：组件库怎么设计？ ⭐⭐

**答：** 原子化分层、受控/非受控、主题 tokens、无障碍、文档/Storybook、版本化；跨端共享逻辑不共享 UI。

### Q3：Monorepo 的优缺点？ ⭐⭐

**答：** 共享代码/统一规范/原子提交；但仓库大、构建慢、权限/发布复杂，需要 pnpm workspace + Turborepo/Nx。

### Q4：什么时候用微前端？ ⭐⭐

**答：** 多团队独立发布、老系统迁移、多技术栈共存；代价是隔离/依赖/通信/监控复杂，小团队不要上。

### Q5：SSR 和 CSR 怎么选？ ⭐⭐

**答：** 首屏/SEO 要求高用 SSR/SSG；交互型后台用 CSR；SSR 要处理服务器成本、浏览器 API、hydration。

### Q6：服务端状态和客户端状态怎么分？ ⭐⭐

**答：** 接口数据用 TanStack Query/SWR 缓存；登录/主题/购物车等客户端状态用 Context/Zustand/Redux；不要把服务端数据复制到全局 store。

### Q7：设计一个电商 App，你怎么拆？ ⭐⭐⭐

**答：** 按页面/领域拆：首页、搜索/列表、详情、购物车、订单/支付、个人中心；API 按资源；服务端状态缓存，购物车登录后同步；图片/列表/预加载做性能；支付以后端回调为准。

### Q8：信息流怎么优化？ ⭐⭐

**答：** 游标分页、虚拟列表、预取、图片懒加载、曝光去重、乐观更新、缓存；视频要控制自动播放。

### Q9：聊天怎么做可靠？ ⭐⭐

**答：** WebSocket + 心跳/重连、消息 ID/ACK/重试、本地存储、离线拉取、未读数、推送；顺序和去重要有服务端保障。

### Q10：中后台权限怎么做？ ⭐⭐

**答：** RBAC，后端返回权限码；前端动态路由/菜单/按钮级控制；后端必须再校验；敏感操作审计。

### Q11：怎么保证多端一致？ ⭐⭐

**答：** 共享 API 契约/业务逻辑/design tokens；UI 按端实现；关键流程每端回归；监控按端区分。
