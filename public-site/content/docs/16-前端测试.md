## 1. 为什么测试

- 防止回归：改 A 功能，弄坏 B 功能。
- 文档作用：测试描述预期行为。
- 重构底气：有测试才敢改。
- 协作：别人改你的代码，测试能兜底。

### 1.1 测试金字塔

```text
        E2E（少量，慢，最接近用户）
      ┌──────────────┐
      │   Integration │
      └──────────────┘
    ┌──────────────────┐
    │   Unit（大量，快） │
    └──────────────────┘
```

- 单元测试：函数/工具/Hook，快、便宜。
- 组件/集成测试：组件 + 交互 + 接口 mock。
- E2E：真实浏览器/真机，跑关键流程。

**前端推荐比例：** 单元 50-70%，组件 20-30%，E2E 5-10%。

## 2. Jest 基础

```bash
npm i -D jest @types/jest ts-jest
```

```js
// sum.js
export function sum(a, b) {
  return a + b;
}

// sum.test.js
import { sum } from './sum';

describe('sum', () => {
  it('adds two numbers', () => {
    expect(sum(1, 2)).toBe(3);
  });

  it('handles negative numbers', () => {
    expect(sum(-1, 2)).toBe(1);
  });
});
```

常用匹配器：

```js
expect(value).toBe(3);            // 严格相等（Object.is）
expect(value).toEqual({ a: 1 });  // 深比较
expect(value).toBeTruthy();
expect(value).toBeNull();
expect(value).toContain('a');
expect(fn).toThrow('error');
expect(value).toBeGreaterThan(1);
```

### 2.1 异步

```js
test('resolves', async () => {
  await expect(fetchUser()).resolves.toEqual({ id: 1 });
});

test('rejects', async () => {
  await expect(fetchUser()).rejects.toThrow('fail');
});

test('callback', (done) => {
  setTimeout(() => {
    expect(1).toBe(1);
    done();
  }, 100);
});
```

### 2.2 Mock

```js
// 模拟模块
jest.mock('./api', () => ({
  fetchUser: jest.fn().mockResolvedValue({ id: 1 }),
}));

// 模拟函数
const fn = jest.fn();
fn('a');
expect(fn).toHaveBeenCalledWith('a');

// 模拟实现
fn.mockReturnValue(1);
fn.mockImplementation((x) => x * 2);
fn.mockResolvedValue({ ok: true });
```

### 2.3 定时器

```js
beforeEach(() => jest.useFakeTimers());
afterEach(() => jest.useRealTimers());

test('debounce', () => {
  const fn = jest.fn();
  const debounced = debounce(fn, 300);

  debounced();
  debounced();

  jest.advanceTimersByTime(299);
  expect(fn).not.toHaveBeenCalled();

  jest.advanceTimersByTime(1);
  expect(fn).toHaveBeenCalledTimes(1);
});
```

### 2.4 Jest 配置

```js
// jest.config.js
module.exports = {
  testEnvironment: 'jsdom',
  setupFilesAfterEnv: ['<rootDir>/jest.setup.js'],
  moduleNameMapper: {
    '\\.(css|less|scss)$': 'identity-obj-proxy',
    '^@/(.*)$': '<rootDir>/src/$1',
  },
  transform: {
    '^.+\\.(t|j)sx?$': 'ts-jest',
  },
};
```

## 3. React Testing Library

> 原则：**像用户一样测试**，不测实现细节。

```bash
npm i -D @testing-library/react @testing-library/jest-dom @testing-library/user-event
```

```jsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import Counter from './Counter';

test('点击按钮后计数增加', async () => {
  render(<Counter />);

  expect(screen.getByText('0')).toBeInTheDocument();

  await userEvent.click(screen.getByRole('button', { name: '+1' }));

  expect(screen.getByText('1')).toBeInTheDocument();
});
```

### 3.1 查询优先级

1. `getByRole`：最接近无障碍/用户。
2. `getByLabelText`：表单。
3. `getByPlaceholderText`：输入框。
4. `getByText`：文本。
5. `getByTestId`：最后手段。

```jsx
screen.getByRole('button', { name: '提交' });
screen.getByLabelText('手机号');
screen.getByPlaceholderText('搜索');
screen.getByTestId('submit-btn');
```

`getBy` 找不到会抛错；`queryBy` 返回 null；`findBy` 异步等待。

### 3.2 异步

```jsx
test('加载用户', async () => {
  render(<UserProfile id={1} />);

  expect(screen.getByText('加载中...')).toBeInTheDocument();

  expect(await screen.findByText('Tom')).toBeInTheDocument();
});
```

### 3.3 表单

```jsx
await userEvent.type(screen.getByLabelText('手机号'), '13800138000');
await userEvent.click(screen.getByRole('button', { name: '登录' }));

expect(await screen.findByText('登录成功')).toBeInTheDocument();
```

## 4. Mock 接口

### 4.1 MSW（推荐）

```bash
npm i -D msw
```

```js
// mocks/server.js
import { setupServer } from 'msw/node';
import { http, HttpResponse } from 'msw';

export const server = setupServer(
  http.get('/api/user', () => {
    return HttpResponse.json({ id: 1, name: 'Tom' });
  })
);
```

```js
// jest.setup.js
import { server } from './mocks/server';

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

### 4.2 `jest.mock`

```js
jest.mock('./api');

import { fetchUser } from './api';

fetchUser.mockResolvedValue({ id: 1 });
```

### 4.3 全局 fetch

```js
global.fetch = jest.fn(() =>
  Promise.resolve({
    ok: true,
    json: () => Promise.resolve({ id: 1 }),
  })
);
```

> 优先 MSW：它拦截真实请求，测试更接近实际。

## 5. Hooks 测试

用 `renderHook`（@testing-library/react）：

```jsx
import { renderHook, act } from '@testing-library/react';
import useCounter from './useCounter';

test('useCounter', () => {
  const { result } = renderHook(() => useCounter());

  expect(result.current.count).toBe(0);

  act(() => {
    result.current.increment();
  });

  expect(result.current.count).toBe(1);
});
```

## 6. React Native 测试

```bash
npm i -D @testing-library/react-native
```

```jsx
import { render, screen, fireEvent, waitFor } from '@testing-library/react-native';
import App from './App';

test('添加待办', async () => {
  render(<App />);

  fireEvent.changeText(screen.getByPlaceholderText('输入待办'), '买牛奶');
  fireEvent.press(screen.getByText('添加'));

  await waitFor(() => {
    expect(screen.getByText('买牛奶')).toBeTruthy();
  });
});
```

原生模块 mock：

```js
jest.mock('react-native/Libraries/Animated/NativeAnimatedHelper');
```

> 不同 RN 版本路径可能变化；用官方 jest preset + 项目自己的 jest setup。

## 7. 小程序测试

### 7.1 组件测试：miniprogram-simulate

```js
const simulate = require('miniprogram-simulate');

const id = simulate.load('/components/goods-card/index');
const comp = simulate.render(id, {
  item: { id: 1, title: '耳机', price: 199 },
});

comp.attach(document.createElement('parent-wrapper'));

expect(comp.querySelector('.card')).toBeTruthy();
expect(comp.querySelector('.card__title').dom.textContent).toContain('耳机');
```

### 7.2 自动化：miniprogram-automator

```js
const automator = require('miniprogram-automator');

const miniProgram = await automator.launch({
  projectPath: process.cwd(),
});

const page = await miniProgram.reLaunch('/pages/index/index');
await page.waitFor(500);

const card = await page.$('.card');
expect(await card.text()).toContain('耳机');

await miniProgram.close();
```

> 需要开发者工具开启自动化端口；适合关键流程/回归。

## 8. E2E

### 8.1 Playwright（Web）

```js
import { test, expect } from '@playwright/test';

test('搜索商品', async ({ page }) => {
  await page.goto('/');
  await page.getByPlaceholder('搜索').fill('phone');
  await expect(page.getByText('iPhone')).toBeVisible();
});
```

### 8.2 Detox（RN）

```js
describe('Todo', () => {
  it('adds a todo', async () => {
    await element(by.id('todo-input')).typeText('买牛奶');
    await element(by.text('添加')).tap();
    await expect(element(by.text('买牛奶'))).toBeVisible();
  });
});
```

### 8.3 Appium

跨 iOS/Android 的 E2E，适合原生/混合 App；配置成本高。

## 9. 覆盖率与 CI

```bash
npx jest --coverage
```

指标：

- Statements：语句覆盖率。
- Branches：分支覆盖率。
- Functions：函数覆盖率。
- Lines：行覆盖率。

建议：

- 工具函数/核心逻辑 80%+。
- UI 组件测关键交互，不追求 100%。
- 覆盖率是参考，不是目标；不要为了覆盖率写无意义测试。

CI：

```yaml
- run: npm ci
- run: npm run lint
- run: npm test -- --coverage
- run: npm run build
```

## 10. 常见坑

| 问题 | 原因 | 解决 |
|---|---|---|
| `act(...)` warning | 状态更新没包在 act 里 | 用 RTL 的 `findBy`/`waitFor`/`userEvent` |
| 测试通过但线上挂 | mock 与真实接口不一致 | 用 MSW/契约测试，补集成测试 |
| 定时器测试慢 | 真等时间 | `jest.useFakeTimers()` |
| 快照频繁失败 | 改了样式/结构 | 少用大快照，测行为 |
| 测试实现细节 | 查内部 state/class | 用 role/text/label 查询 |
| 异步不稳定 | 没等请求/渲染 | `findBy`/`waitFor`，避免 sleep |
| 测试互相污染 | 全局状态/模块缓存 | `beforeEach` 重置，`jest.resetModules` |

## 11. 面试高频

### Q1：测试金字塔是什么？ ⭐⭐

**答：** 底层大量单元测试，中层组件/集成测试，顶层少量 E2E。越往下越快、越便宜；越往上越接近用户、越慢。

### Q2：Jest 和 React Testing Library 的分工？ ⭐⭐⭐

**答：** Jest 是测试运行器/断言/mock；RTL 是渲染和查询工具，强调像用户一样测试。两者配合：Jest 跑测试，RTL 渲染组件、找元素、模拟交互。

### Q3：RTL 的查询优先级？ ⭐⭐

**答：** role > label > placeholder > text > testId；role 最接近无障碍和用户行为，testId 是最后手段。

### Q4：怎么 mock 接口？ ⭐⭐⭐

**答：** 优先 MSW 拦截真实请求，按 URL/method 返回 mock；简单场景用 jest.mock 模拟模块；测试结束重置 handler，避免互相污染。

### Q5：怎么测异步组件？ ⭐⭐

**答：** 用 `findBy...`/`waitFor` 等待元素出现，用 `userEvent` 模拟交互；不要用固定 sleep。

### Q6：怎么测定时器/防抖？ ⭐⭐

**答：** `jest.useFakeTimers()`，调用后 `jest.advanceTimersByTime(ms)`，断言调用次数；结束恢复 real timers。

### Q7：怎么测 React Hook？ ⭐⭐

**答：** 用 `renderHook` + `act`，调用 hook 返回的方法，断言 `result.current`；异步用 `waitFor`。

### Q8：RN 怎么测试？ ⭐⭐

**答：** 用 `@testing-library/react-native` 渲染、`fireEvent`/`userEvent` 交互、`waitFor` 等异步；原生模块用 jest mock；关键流程用 Detox E2E。

### Q9：小程序怎么测试？ ⭐⭐

**答：** 组件用 miniprogram-simulate，页面/流程用 miniprogram-automator 或开发者工具自动化；核心是选择器、事件、setData 后的渲染断言。

### Q10：E2E 工具怎么选？ ⭐⭐

**答：** Web 用 Playwright/Cypress；RN 用 Detox；跨原生/混合用 Appium。看团队、平台、稳定性。

### Q11：覆盖率越高越好吗？ ⭐⭐

**答：** 不是。覆盖率只说明代码被执行，不说明断言有效；核心逻辑覆盖，UI 测关键交互，避免为了数字写无意义测试。

### Q12：测试通过但线上出问题，为什么？ ⭐⭐

**答：** mock 与真实接口不一致、测试没覆盖集成/边界、环境差异、异步时序；需要契约测试/集成测试/监控兜底。

### Q13：快照测试怎么用？ ⭐

**答：** 适合稳定的纯展示组件/序列化结构；不要用大快照测整个页面，变更时频繁失败且没人看；优先断言行为。

### Q14：CI 里怎么跑测试？ ⭐⭐

**答：** `npm ci` → lint → test --coverage → build；失败阻断合并；测试要稳定、可重复、无外网依赖。
