# 07 · 前端工程化

> 目标：理解一个前端项目从“写代码”到“上线”的完整链路；能独立配置 Webpack、管理依赖、用 Git 协作、做基本性能优化。
>
> 标记：⭐⭐⭐ 必须会｜⭐⭐ 要理解｜⭐ 了解即可

---

## 1. 什么是前端工程化

前端工程化 = 用工具和规范，把“写代码 → 调试 → 构建 → 测试 → 部署 → 监控”变成可重复、可协作、可自动化的流程。

包含：

- **模块化**：代码拆成模块，按需引入。
- **组件化**：UI 拆成组件。
- **规范化**：命名、目录、代码风格、提交信息。
- **自动化**：构建、检查、测试、部署。
- **性能**：构建优化、加载优化、运行时优化。
- **监控**：错误、性能、埋点。

```text
开发环境：VS Code + ESLint + Prettier + Git
    ↓
本地开发：Vite/Webpack Dev Server + HMR
    ↓
代码检查：ESLint + TypeScript + 单元测试
    ↓
构建：Babel/SWC + Webpack/Rollup/Vite
    ↓
产物：HTML/CSS/JS/图片，压缩、hash、sourcemap
    ↓
部署：CDN/Nginx/云平台
    ↓
监控：Sentry/性能平台/埋点
```

## 2. Node.js 基础 ⭐⭐

Node.js 让 JS 跑在浏览器之外，是前端工程化的基础。

### 2.1 运行

```bash
node -v
node hello.js
node -e "console.log(1 + 1)"
```

### 2.2 模块系统

CommonJS（Node 传统）：

```js
// math.js
const add = (a, b) => a + b;
module.exports = { add };

// main.js
const { add } = require('./math');
console.log(add(1, 2));
```

ES Module（在 `package.json` 里加 `"type": "module"`，或用 `.mjs`）：

```js
// math.js
export const add = (a, b) => a + b;

// main.js
import { add } from './math.js';
```

### 2.3 常用内置模块

```js
const fs = require('node:fs');
const path = require('node:path');
const http = require('node:http');
const os = require('node:os');

// 读文件
const text = fs.readFileSync(path.join(__dirname, 'data.json'), 'utf8');
const data = JSON.parse(text);

// 写文件
fs.writeFileSync('output.json', JSON.stringify(data, null, 2));

// 判断文件是否存在
if (fs.existsSync('output.json')) {
  console.log('存在');
}

// 路径
path.join('src', 'pages', 'index.js'); // src/pages/index.js
path.resolve('src');                   // 绝对路径
path.extname('a.png');                 // .png

// 一个最简单的 HTTP 服务
http.createServer((req, res) => {
  res.setHeader('Content-Type', 'application/json; charset=utf-8');
  res.end(JSON.stringify({ code: 0, data }));
}).listen(3000, () => {
  console.log('http://localhost:3000');
});
```

### 2.4 Node 的事件循环

Node 的事件循环分阶段：

```text
timers → pending callbacks → idle/prepare → poll → check → close callbacks
```

- `setTimeout` / `setInterval` 在 timers。
- `setImmediate` 在 check。
- I/O 回调在 poll。
- 每个阶段之间清空 `process.nextTick` 和 Promise 微任务。
- `process.nextTick` 优先于 Promise。

```js
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
Promise.resolve().then(() => console.log('promise'));
process.nextTick(() => console.log('nextTick'));

// 典型输出：nextTick promise 先执行；顶层 timeout/immediate 的顺序不固定，取决于启动耗时
```


### 3.2 `package.json` 关键字段

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "lint": "eslint .",
    "format": "prettier --write ."
  },
  "dependencies": {
    "react": "^18.3.1",
    "react-dom": "^18.3.1"
  },
  "devDependencies": {
    "vite": "^5.4.0",
    "eslint": "^9.11.0"
  },
  "engines": {
    "node": ">=20"
  }
}
```

| 字段 | 作用 |
|---|---|
| `scripts` | 命令别名，`npm run xxx` |
| `dependencies` | 运行时依赖，会打进去 |
| `devDependencies` | 开发/构建/测试依赖，不打包 |
| `peerDependencies` | 宿主环境提供，例如组件库要求 React |
| `engines` | Node 版本要求 |
| `private` | 防止误发布到 npm |
| `type` | `module` 表示 ESM |

### 3.3 语义化版本 semver

```text
主版本.次版本.补丁
major.minor.patch
1.2.3
```

| 写法 | 含义 |
|---|---|
| `1.2.3` | 精确版本 |
| `^1.2.3` | 允许 1.x.x，不升到 2.0.0 |
| `~1.2.3` | 允许 1.2.x，不升到 1.3.0 |
| `>=1.2.3 <2.0.0` | 范围 |
| `*` / `latest` | 最新（不可控，避免） |

- **lockfile**（`package-lock.json` / `pnpm-lock.yaml`）锁定实际安装版本，保证团队一致。
- `npm ci` 按 lockfile 安装，适合 CI。
- 升级依赖后要跑测试，主版本升级可能有 breaking change。

## 5. Webpack ⭐⭐⭐

Webpack 是模块打包器：从入口出发，递归分析依赖，把各种资源（JS/CSS/图片/字体）转成模块，最终输出 bundle。

### 5.1 五个核心概念

| 概念 | 作用 |
|---|---|
| `entry` | 入口，从哪里开始打包 |
| `output` | 输出到哪里、叫什么名字 |
| `loader` | 把非 JS 文件/新语法转换成 Webpack 能处理的模块 |
| `plugin` | 在构建生命周期上挂钩子，做更复杂的事 |
| `mode` | development/production，内置不同优化 |

### 5.2 构建流程（简化）

```text
1. 初始化参数，创建 Compiler
2. 加载 plugin，注册钩子
3. 从 entry 开始编译
4. 递归解析依赖，调用对应 loader 转换模块
5. 构建模块依赖图（ModuleGraph）
6. 生成 chunk，优化（tree shaking、压缩、分割）
7. 输出文件到 output.path
```

Loader 从右往左、从下往上执行：

```js
use: ['style-loader', 'css-loader', 'postcss-loader']
// 实际执行顺序：postcss-loader → css-loader → style-loader
```

### 5.3 常用 loader

| loader | 作用 |
|---|---|
| `babel-loader` | 用 Babel 转 JS 新语法 |
| `ts-loader` / `esbuild-loader` | 转 TypeScript |
| `css-loader` | 解析 CSS 的 import/url |
| `style-loader` | 把 CSS 插入 `<style>` |
| `postcss-loader` | 自动加前缀、转换新 CSS |
| `sass-loader` | 编译 Sass |
| `mini-css-extract-plugin` 的 loader | 把 CSS 抽成独立文件 |
| `asset modules`（内置） | 处理图片/字体 |

### 5.4 常用 plugin

| plugin | 作用 |
|---|---|
| `HtmlWebpackPlugin` | 生成 HTML 并自动引入 JS/CSS |
| `MiniCssExtractPlugin` | 抽取 CSS 文件 |
| `DefinePlugin` | 定义全局常量（环境变量） |
| `CopyWebpackPlugin` | 复制静态资源 |
| `CleanWebpackPlugin` | 清理 dist（Webpack 5 可用 `output.clean`） |
| `BundleAnalyzerPlugin` | 分析包体积 |

### 5.5 完整配置（逐行注释）

```js
// webpack.config.js
const path = require('node:path');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');
const { DefinePlugin } = require('webpack');

module.exports = (env, argv) => {
  // argv.mode 由命令行 --mode 传入
  const isProd = argv.mode === 'production';

  // 生产环境才抽离 CSS，开发环境用 style-loader 支持热更新
  const plugins = [
    new HtmlWebpackPlugin({
      template: './public/index.html', // 模板
      minify: isProd,                  // 生产环境压缩 HTML
    }),
    new DefinePlugin({
      // 代码里可以用 process.env.NODE_ENV
      'process.env.NODE_ENV': JSON.stringify(argv.mode || 'development'),
    }),
  ];

  if (isProd) {
    plugins.push(
      new MiniCssExtractPlugin({
        filename: 'css/[name].[contenthash:8].css',
      })
    );
  }

  return {
    // 入口
    entry: './src/index.js',

    // 输出
    output: {
      path: path.resolve(__dirname, 'dist'),
      filename: isProd ? 'js/[name].[contenthash:8].js' : 'js/[name].js',
      chunkFilename: isProd ? 'js/[name].[contenthash:8].chunk.js' : 'js/[name].chunk.js',
      publicPath: '/',   // 资源基础路径，部署到子目录时要改
      clean: true,       // 每次构建前清空 dist
    },

    // 解析规则
    resolve: {
      extensions: ['.js', '.jsx', '.json'], // 省略后缀
      alias: {
        '@': path.resolve(__dirname, 'src'), // @/components/Button
      },
    },

    // 模块转换规则
    module: {
      rules: [
        {
          test: /\.(js|jsx)$/,
          exclude: /node_modules/,
          use: 'babel-loader', // 交给 Babel 转语法
        },
        {
          test: /\.css$/,
          use: [
            isProd ? MiniCssExtractPlugin.loader : 'style-loader',
            'css-loader',
            'postcss-loader',
          ],
        },
        {
          test: /\.(png|jpe?g|gif|webp|svg)$/i,
          type: 'asset', // 小于 8KB 转 base64，大于则输出文件
          parser: {
            dataUrlCondition: { maxSize: 8 * 1024 },
          },
          generator: {
            filename: 'images/[name].[hash:8][ext]',
          },
        },
        {
          test: /\.(woff2?|ttf|otf|eot)$/i,
          type: 'asset/resource',
          generator: {
            filename: 'fonts/[name].[hash:8][ext]',
          },
        },
      ],
    },

    plugins,

    // 优化
    optimization: {
      splitChunks: {
        chunks: 'all', // 同步/异步 chunk 都分割
        cacheGroups: {
          vendor: {
            test: /[\\/]node_modules[\\/]/, // 第三方依赖单独打包
            name: 'vendors',
            priority: -10,
          },
          common: {
            minChunks: 2, // 被两个以上 chunk 引用的公共代码
            name: 'common',
            priority: -20,
            reuseExistingChunk: true,
          },
        },
      },
      runtimeChunk: 'single', // 运行时代码单独抽离，利于缓存
    },

    // 开发服务器
    devServer: {
      static: './dist',
      hot: true,             // 热更新
      port: 3000,
      open: true,
      historyApiFallback: true, // SPA 路由刷新不 404
      proxy: {
        // 开发环境代理，解决跨域
        '/api': {
          target: 'http://localhost:8080',
          changeOrigin: true,
          // pathRewrite: { '^/api': '' },
        },
      },
    },

    // sourcemap：生产用 source-map，开发用 eval-cheap-module-source-map
    devtool: isProd ? 'source-map' : 'eval-cheap-module-source-map',

    // 构建缓存，二次构建更快
    cache: {
      type: 'filesystem',
    },

    // 性能提示
    performance: {
      hints: false,
    },
  };
};
```

### 5.6 常用优化

| 优化 | 做法 |
|---|---|
| 缩小构建范围 | `exclude: /node_modules/`、`include` |
| 缓存 | `cache: { type: 'filesystem' }`、babel-loader 缓存 |
| 多进程 | `thread-loader`、`esbuild-loader` |
| Tree Shaking | ESM + `sideEffects: false` + 生产模式 |
| 代码分割 | 动态 `import()`、`splitChunks` |
| 压缩 | `terser-webpack-plugin`、`css-minimizer-webpack-plugin` |
| 资源压缩 | 图片压缩、字体子集化 |
| 长效缓存 | `[contenthash]` |
| 分析体积 | `webpack-bundle-analyzer` |

### 5.7 Tree Shaking

前提：

1. 使用 ES Module（静态 import/export）。
2. 生产模式（`mode: 'production'`）。
3. `package.json` 里 `"sideEffects": false`，或标注有副作用的文件。
4. 没有被使用的导出才能删除。

```js
// utils.js
export function used() {}
export function unused() {}

// main.js
import { used } from './utils';
used();
// unused 会被删除
```

CommonJS 是运行时加载，通常无法可靠 tree shaking。

### 5.8 热更新 HMR

修改代码后只替换变化的模块，不刷新页面，保留页面状态。

```js
// 业务代码通常不需要手动写，框架的 loader 会处理
if (module.hot) {
  module.hot.accept('./App', () => {
    // 重新渲染
  });
}
```

React 用 `react-refresh`，Vue 用 `vue-loader` 内置 HMR。

## 6. Gulp ⭐

Gulp 是基于**流（stream）**的任务运行器，适合处理静态资源、老项目构建。

```js
// gulpfile.js
const { src, dest, series, parallel, watch } = require('gulp');
const sass = require('gulp-sass')(require('sass'));
const cleanCSS = require('gulp-clean-css');
const terser = require('gulp-terser');
const rename = require('gulp-rename');
const del = require('del');

// 清理
async function clean() {
  await del(['dist']);
}

// 编译 Sass → 压缩 → 输出
function styles() {
  return src('src/styles/**/*.scss')
    .pipe(sass().on('error', sass.logError))
    .pipe(cleanCSS())
    .pipe(rename({ suffix: '.min' }))
    .pipe(dest('dist/css'));
}

// 压缩 JS
function scripts() {
  return src('src/js/**/*.js')
    .pipe(terser())
    .pipe(rename({ suffix: '.min' }))
    .pipe(dest('dist/js'));
}

// 监听
function watchFiles() {
  watch('src/styles/**/*.scss', styles);
  watch('src/js/**/*.js', scripts);
}

// 串行/并行
exports.build = series(clean, parallel(styles, scripts));
exports.default = series(clean, parallel(styles, scripts), watchFiles);
```

Webpack vs Gulp：

| 维度 | Webpack | Gulp |
|---|---|---|
| 定位 | 模块打包器 | 任务运行器 |
| 核心 | 依赖图、loader/plugin | 文件流、task |
| 适合 | 现代 SPA/组件化项目 | 静态资源处理、老项目 |
| 学习成本 | 高 | 低 |

## 7. Vite ⭐⭐

Vite 是新一代构建工具：

- 开发环境：利用浏览器原生 ESM，按需编译，启动快。
- 依赖预构建：用 esbuild 把 CommonJS 依赖转成 ESM。
- 生产构建：Rollup。
- HMR 基于 ESM，更新快。

```js
// vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
      },
    },
  },
  build: {
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],
        },
      },
    },
  },
});
```

```js
// 环境变量：只有 VITE_ 开头会暴露给客户端

```


### 9.4 撤销

```bash
# 撤销工作区修改（危险：会丢失未提交内容）
git restore src/App.jsx

# 取消暂存
git restore --staged src/App.jsx

# 修改最近一次提交（本地未推送）
git commit --amend

# 回退提交，保留改动到工作区
git reset --soft HEAD~1

# 回退提交，保留改动到暂存区
git reset --mixed HEAD~1

# 回退提交，丢弃改动（非常危险）
git reset --hard HEAD~1

# 生成一个反向提交，安全（已推送用这个）
git revert <commit-id>
```

> 已推送到共享分支的提交，不要用 `reset --hard`，用 `revert`。

### 9.5 暂存与挑拣

```bash
git stash            # 临时保存未提交改动
git stash list
git stash pop        # 恢复并删除
git stash apply      # 恢复但保留

git cherry-pick <commit-id>  # 把某个提交应用到当前分支
```

### 9.6 merge vs rebase

```text
merge：保留分支历史，产生一个合并提交
rebase：把当前分支的提交“搬”到目标分支后面，历史更线性
```

```bash
git switch feature/list
git rebase main
```

手动改成想要的结果，删掉标记，然后：

```bash

# 或 rebase 时
```

### 10.3 Axios 封装（逐行注释）

```js
// src/utils/http.js
import axios from 'axios';

// 创建实例，统一配置
const http = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 10000,
});

// 请求拦截器：每次请求前加 token
http.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// 响应拦截器：统一处理业务码和错误
http.interceptors.response.use(
  (response) => {
    const res = response.data;

    // 约定：code === 0 表示成功
    if (res.code === 0) {
      return res.data; // 直接返回业务数据
    }

    // 业务错误
    return Promise.reject(new Error(res.message || '请求失败'));
  },
  (error) => {
    // HTTP 错误
    if (error.response) {
      const { status, data } = error.response;

      if (status === 401) {
        // 未登录：清除 token，跳登录
        localStorage.removeItem('token');
        // location.href = '/login';
      }

      return Promise.reject(new Error(data?.message || `HTTP ${status}`));
    }

    // 超时/断网
    if (error.code === 'ECONNABORTED') {
      return Promise.reject(new Error('请求超时，请重试'));
    }

    return Promise.reject(new Error('网络异常，请检查网络'));
  }
);

export default http;
```

```js
// 使用
import http from '@/utils/http';

export function getGoods(params) {
  return http.get('/goods', { params });
}

export function getGoodsDetail(id) {
  return http.get(`/goods/${id}`);
}

export function createOrder(data) {
  return http.post('/orders', data);
}
```

## 12. 性能优化体系 ⭐⭐⭐

### 12.1 指标

| 指标 | 含义 | 目标 |
|---|---|---|
| TTFB | 首字节时间 | < 800ms |
| FCP | 首次内容绘制 | < 1.8s |
| LCP | 最大内容绘制 | < 2.5s |
| INP | 交互到下一次绘制 | < 200ms |
| CLS | 累积布局偏移 | < 0.1 |

> FID 已被 INP 取代，面试时提到 INP 会加分。

### 12.2 加载阶段

- 代码分割：路由懒加载、动态 import。
- Tree Shaking。
- 压缩 JS/CSS/HTML。
- 图片：WebP/AVIF、压缩、`srcset`、懒加载、CDN。
- 字体：`font-display: swap`、子集化、预加载。
- 预加载：`preload`、`prefetch`、`preconnect`。
- HTTP 缓存：强缓存 + 协商缓存。
- CDN。
- SSR/SSG（首屏要求高的项目）。

### 12.3 运行时

- 长列表虚拟滚动。
- 防抖/节流。
- 减少重渲染（React memo/useCallback）。
- 避免强制同步布局。
- 动画用 transform/opacity。
- Web Worker 处理大计算。
- 图片解码 `decoding="async"`。
- 组件懒加载。
- 内存泄漏排查。

### 12.4 构建阶段

- 缓存（filesystem、babel cache）。
- 多线程（thread-loader）。
- 缩小 loader 范围。
- 合理 splitChunks。
- contenthash 长效缓存。
- 包体积分析。

### 12.5 缓存策略

```text
index.html：no-cache（每次都校验）
带 hash 的 JS/CSS：max-age=31536000, immutable
图片/字体：长期缓存
API：根据业务设置
```

### 12.6 监控

- 错误监控：Sentry、自建。
- 性能监控：`PerformanceObserver`、web-vitals。
- 埋点：用户行为、页面停留、转化。
- 日志：接口失败、白屏、卡顿。

## 14. 面试高频题

### Q1：Webpack 的构建流程？ ⭐⭐⭐

**答：** 从 entry 开始，递归解析依赖，构建模块依赖图；每个模块根据规则交给 loader 转换；plugin 在生命周期钩子上做扩展；最后生成 chunk，做 tree shaking、压缩、代码分割，输出到 output。核心是 Compiler 和 Compilation，基于 Tapable 的钩子机制。

### Q2：loader 和 plugin 的区别？ ⭐⭐⭐

**答：** loader 是模块转换器，处理单个文件的转换，比如把 JSX 转 JS、SCSS 转 CSS，配置在 module.rules 里，从右往左执行；plugin 是插件，监听构建生命周期钩子，能做更复杂的事，比如生成 HTML、抽离 CSS、定义环境变量。

### Q3：Tree Shaking 的原理？ ⭐⭐⭐

**答：** 基于 ES Module 的静态结构，打包时分析哪些导出被使用，删除未使用的代码。前提是 ESM、生产模式、`sideEffects` 配置正确。CommonJS 运行时加载，通常无法可靠 tree shaking。

### Q4：Webpack 怎么优化构建速度？ ⭐⭐

**答：** 缩小 loader 范围（exclude/include）；开启 filesystem 缓存和 babel 缓存；多线程 thread-loader/esbuild-loader；减少 resolve 范围；生产环境关闭 sourcemap 或改用 cheap；使用 splitChunks 合理分包；升级 Webpack 版本。

### Q5：Webpack 怎么优化产物体积？ ⭐⭐

**答：** Tree shaking；代码分割（动态 import、splitChunks）；压缩 JS/CSS；图片压缩和合适的格式；按需引入组件库；externals 把大依赖放 CDN；分析 bundle 找大模块。

### Q6：HMR 是什么？ ⭐⭐

**答：** 热模块替换，修改代码后只替换变化的模块，不刷新页面，保留页面状态。Webpack 通过 devServer 和 HMR runtime 实现；React 用 react-refresh，Vue 用 vue-loader。

### Q7：Vite 为什么快？ ⭐⭐

**答：** 开发环境利用浏览器原生 ESM，按需编译，不打包整个项目；依赖用 esbuild 预构建，速度快；HMR 基于 ESM，只更新变化的模块。生产构建用 Rollup。

### Q8：npm 的 `^` 和 `~` 有什么区别？ ⭐⭐

**答：** `^1.2.3` 允许更新到 1.x.x 的最新版，不跨主版本；`~1.2.3` 只允许 1.2.x，不跨次版本。lockfile 锁定实际版本，CI 用 `npm ci` 保证一致。

### Q9：`dependencies` 和 `devDependencies` 的区别？ ⭐⭐

**答：** dependencies 是运行时依赖，会被打包/部署；devDependencies 是开发、构建、测试用的工具，不进入生产包。组件库的 React 应该放 peerDependencies，避免重复安装。

### Q10：Git merge 和 rebase 的区别？ ⭐⭐⭐

**答：** merge 保留分支历史，生成合并提交；rebase 把当前分支的提交搬到目标分支后面，历史更线性。rebase 会改写提交 hash，不能用于已经推送到共享分支的提交。

### Q11：Git reset 和 revert 的区别？ ⭐⭐

**答：** reset 是移动分支指针，会改写历史，适合本地未推送的提交；revert 是生成一个反向提交，历史保留，适合已推送的提交。`reset --hard` 会丢弃工作区改动，慎用。

### Q12：前端怎么做跨域？ ⭐⭐

**答：** 开发环境用 Webpack/Vite 代理；生产环境后端配置 CORS、同域部署或 Nginx 反向代理；JSONP 只支持 GET，已很少用；WebSocket 不受同源限制。

### Q13：前端性能优化有哪些？ ⭐⭐⭐

**答：** 分三个阶段：加载阶段（代码分割、tree shaking、压缩、图片优化、CDN、缓存、预加载）；运行时（虚拟列表、防抖节流、减少重渲染、动画用 transform、Web Worker）；构建阶段（缓存、多线程、分包、体积分析）。指标看 LCP、INP、CLS。

### Q14：什么是 sourcemap？生产环境要不要开？ ⭐⭐

**答：** sourcemap 是压缩代码到源码的映射，方便调试。生产环境可以生成但不要公开部署，上传到监控平台用于还原错误栈；或者用 hidden-source-map，只保留映射文件不引用。

### Q15：ESLint 和 Prettier 的区别？ ⭐⭐

**答：** ESLint 检查代码质量和潜在错误（未使用变量、Hooks 规则），Prettier 只管格式（缩进、引号、换行）。两者配合使用，ESLint 负责逻辑，Prettier 负责风格，避免规则冲突。
