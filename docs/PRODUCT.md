# 职跃 OfferPath · 产品分析

## 1. 第一性原理

求职准备的真正瓶颈，不是「资料不够」，而是：

1. **不知道学什么**：资料无限，目标岗位的要求有限，缺的是裁剪。
2. **学完不会用**：长视频/长文档完成率低，缺少即时练习与反馈。
3. **会做不会说**：笔试能过，技术面无法把项目讲清楚，也扛不住追问。
4. **错误没有闭环**：做错的题不复习，同一个坑反复踩。
5. **时间压力不同**：有人只有 3 天，有人有 12 周，不能用同一条学习路径。

因此产品的核心闭环是：

> 目标诊断 → 小颗粒学习 → 章节练习 → 错题重做 → 模拟面试追问 → 全过程记录 → 计划调整

内容必须复用同一份「知识点 / 题 / 面试题」资产，不按模式复制课程。

## 2. 用户与场景

| 用户 | 真实状态 | 核心诉求 | 产品入口 |
| --- | --- | --- | --- |
| A. 基础薄弱者 | 概念不成体系，看长课容易放弃 | 每次只学一个小点，马上做题 | 系统学习 |
| B. 急求职者 | 有明确 JD，1–14 天内面试 | 只看会考的，背完能练，能模拟面 | 急冲计划 |
| C. 规划型用户 | 6–12 周转岗/进阶 | 结构化路线、阶段里程碑、能力缺口 | 职业规划 |
| D. 面试受挫者 | 技术面答不到点上 | 针对简历项目追问、错误引导、参考回答 | 模拟面试 |

三个入口共享等级（初级/中级/高级）与内容库；用户可切换，不产生两套进度。

## 3. 功能拆解

### F1 微课学习（基础薄弱）
- 每章 3 个知识点，每节 3–6 分钟：一句话结论 → 关键点 → 例子 → 坑 → 面试表达。
- 完成一节立即标记进度；章节学完进入「5 道题 + 1 道代码题」练习。
- 记录：学习完成、练习提交、错题、重做。

### F2 急冲计划（短期、目标明确）
- 输入：简历、岗位 JD、方向、等级、准备周期（3/7/14 天）。
- 处理：提取简历/JD 技能词，计算匹配与缺口，优先级排序知识点，编入每日任务。
- 输出：匹配说明、需背诵要点、每日学习/练习/代码题/模拟面试任务，可逐项完成。
- 明示实现方式：可解释规则引擎（非大模型），展示提取证据，不伪造「AI 评分」。

### F3 职业规划（中长期）
- 输入：目标方向（当前开放移动端、全栈）、等级、目标公司 JD（可选）、周期（4/8/12 周）。
- 输出：分阶段路线图（补基础 → 核心能力 → 面试冲刺）、技能覆盖表、阶段任务与验收标准。
- 其他方向以「规划中」呈现，不提供假课程。

### F4 模拟面试
- 依据简历项目与 JD 组题：项目深挖 + 知识题 + 追问。
- 回答后给出评分、命中要点、遗漏要点、参考回答。
- 低分 → 引导（展示一条提示）并允许重答一次；高分 → 自动追问更深的问题。
- 结束生成报告：均分、优势、缺口、推荐复习知识点；全程留痕。

### F5 记录与复盘
- 学习进度、练习成绩、错题与重做、代码提交、计划、面试会话全部持久化。
- 首页聚合今日任务、正确率、待复习错题、最近动态。
- 错题可单独重做；答对后标记已解决。

## 4. 范围（MVP）

### 做
- 网页端，移动优先响应式。
- 移动端开发（Android/Kotlin + 跨端意识）与全栈开发两个方向，各 3 个等级 × 3 章。
- 本地账号体系、数据隔离、SQLite 持久化。
- 微课、章节练习、代码题、急冲、规划、模拟面试、记录、错题。
- 可解释的简历/JD 分析；无外部 AI 依赖也能完整运行。
- 规范文档、逐需求提交、自动化测试、浏览器验收。

### 暂不做（有当前需求依据才做）
- 支付、会员、社区、排行榜。
- 真实大模型调用（当前无密钥/无验收基线；若接入需单独需求与失败降级设计）。
- 服务端执行用户代码（全栈题在浏览器沙箱执行；移动端代码题采用参考实现 + 自查评分）。
- 多租户组织、消息推送、简历生成导出。
- iOS/Flutter 专项、后端、前端、数据等方向的正式课程（先规划）。
- 面向公网的高可用部署（MVP 为单实例 SQLite；上线前另行需求）。

## 5. 成功标准（MVP 验收）

1. 新用户可注册、选方向与等级，完成一节微课→章节练习→查看错题→重做。
2. 上传简历 + JD 能在数秒内生成含技能缺口、每日任务、代码题的急冲计划，且任务可跳转完成。
3. 模拟面试至少 5 题，能展示评分、参考回答；低分给提示并可重答，高分触发追问；结束后有报告。
4. 所有学习、练习、错题、重做、代码、计划、面试均有记录，且用户之间彼此不可见。
5. 两个方向的初中高级课程与题库通过结构校验；类型检查、单元/集成测试通过；桌面与移动视口真实浏览器走通主流程。

## 6. 风险与取舍

| 风险 | 取舍 |
| --- | --- |
| 用户期待「AI 生成」，实现为规则引擎 | UI 明确「可解释匹配」，展示命中证据；LLM 适配作为后续独立需求，不在 MVP 假装 AI |
| 内容质量决定留存 | 内容结构化、可校验、按等级分层；宁可少而准，不堆长文 |
| 单机 SQLite 不适合横向扩展 | MVP 单实例可接受；repository 层隔离，后续可替换 Postgres |
| 用户代码安全 | 全栈题仅在带 CSP 的沙箱 iframe/Worker 中执行；移动端不执行代码 |
| 简历隐私 | 仅存本地库，按用户隔离；不在日志/响应中泄露他人数据 |

## 7. 非功能要求

- 页面首屏在本地 1s 级可用；不引入外部字体/CDN 依赖。
- 所有写操作校验会话与同源；密码仅存 scrypt 哈希；会话令牌仅存哈希。
- 键盘可用、表单有 label、状态有文字反馈；移动端底部导航，桌面侧边栏。
- 失败状态可恢复：网络错误提示重试，空数据有引导，不出现死路。
