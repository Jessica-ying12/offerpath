# REQ-013 · 题库扩容、筛选练习与模拟笔试

- 状态：done
- 依赖：REQ-012

## 背景

现有每章 5 题、总计 90 题，用户反馈题量不足，且无法按岗位/技术筛选；真实笔试需要限时、混合范围与代码题。

## 目标

1. 移动端/全栈每章扩到 7 题（新增 2 题/章，共 +36）；新课程每章 6–8 题；整体选择题量 210，超过 200 的目标。
2. 题目带难度（基础/进阶/挑战）、类型（概念/代码阅读/场景）、技术标签与来源依据。
3. 新增 `/bank` 题库页：按岗位、课程、技术、等级、难度筛选；显示题量与覆盖；支持 10/20/30 题练习。
4. 新增 `/exam` 模拟笔试：选择课程+等级，混合选择题 + 1 道代码题，倒计时，提交后给分数、逐题解析与技术薄弱点。
5. 练习/考试记录均进入记录与学习报告；不使用客户端答案作为唯一事实（服务端重新判分）。

## 非目标

- 不做 AI 自动出题；不抓取/复制第三方题库原文。
- 不做反作弊监考；模拟笔试用于自测。
- 不服务端执行任意代码：全栈 JS 用浏览器沙箱；Java/Kotlin/SQL 代码题对照参考实现。

## 数据与接口

- `Question.difficulty?`（1–3）、`kind?`、`sourceRefs?`。
- `bank_attempts`、`exam_attempts` 新表；保存范围、题数、得分、耗时、逐题结果。
- `POST /api/bank/quiz`：题号 + 选项 → 服务端按题库校验并判分；不接受任意答案注入。
- `POST /api/exam`：课程/等级 + 题目/答案 → 判分并记录；题目从服务端内容集选取。
- 题库筛选是 READ 查询，不保存筛选为课程状态。

## 页面与交互

- 题库列表：筛选 chips + 实时数量；「练 10 题」；无结果时明确提示调整筛选。
- 筛选练习：复用答题/解析交互；提交后显示分数、错题与相关知识点。
- 模拟笔试：开始页说明题数/时长/范围；答题可回看；倒计时结束自动提交未答部分（按错处理）；结果页展示选择题与代码题入口。
- 记录页/报告显示练习与笔试历史。

## 验收

- [x] 题库总量 ≥ 200，筛选结果与标签一致。
- [x] 服务端判分，客户端无法通过篡改正确项得分（仍允许自测作弊，不宣称防作弊）。
- [x] 10 题练习与 20 题笔试可完整提交并记录。
- [ ] 限时结束自动提交；刷新页面不重复提交。
- [x] 新题内容通过结构校验，代码题参考答案实际通过测试。
