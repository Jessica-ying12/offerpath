# REQ-000 · 产品拆解与工程规范基线

- 状态：done
- 关联：无代码；为后续所有 REQ 的前置约束

## 背景

用户需要在没有持续人工指挥的情况下推进一个完整产品。先固定问题定义、范围、体验原则、技术边界与提交纪律，避免「边做边漂移」。

## 目标

1. 从真实求职问题拆解出三类用户与核心闭环。
2. 明确两个首发方向（移动端、全栈）、三个等级、MVP 范围与非目标。
3. 定下技术栈与职责边界：Next.js + SQLite + 只读内容 + 纯函数引擎 + 服务层。
4. 制定开发、AI 协作、内容、提交规范，并建立逐需求方案机制。

## 非目标

- 不在本需求实现任何业务页面。
- 不选定超过 MVP 需要的依赖。
- 不为其他方向提前建设课程或抽象。

## 关键决策

- **规则引擎而非 LLM**：无密钥/无验收条件；以可解释匹配完成当前闭环，未来单独需求接入 LLM。
- **SQLite 单实例**：当前用户量未知，优先完整闭环与本地可运行；repository 隔离便于替换。
- **移动端方向以 Android/Kotlin 为主，含跨端意识**：代码题可在本地呈现参考实现，不假设执行 Kotlin。
- **全栈代码题在客户端沙箱执行**：JS 同步纯函数，CSP + opaque origin + Worker 超时。
