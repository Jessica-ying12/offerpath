# REQ-011 · 知识点精讲与权威来源

- 状态：done
- 依赖：REQ-003 / REQ-009
- 关联：REQ-012 内容扩展

## 背景

用户明确指出不需要视频“微课”，要按章节、逐个知识点进行教学；同时希望内容有可核验的权威依据，而不是编造。现有 lesson 页面已经是文本微课，但命名与信息结构容易被理解为视频或摘要卡片，需要升级为“精讲 + 步骤 + 检查理解 + 来源”。

## 目标

1. 全局把“微课”改为“知识点精讲/知识点”，说明无视频。
2. 章节内按顺序展示 3 个知识点；每个知识点有明确目标、讲解、示例、易错点、面试表达。
3. 每个章节附官方参考来源（章节级 2–4 个链接），可打开核对。
4. 删除“微课=短视频”的暗示；所有教学为文本 + 代码 + 练习。
5. 保留小颗粒、可完成的节奏，不把页面变成长文教材。

## 非目标

- 不做视频、直播、音频。
- 不复制外部教材或付费题库。
- 不追求覆盖所有知识；按求职高频与等级取舍。

## 内容结构

章节：
```
级别 → 章节 → 3 个知识点（每个 3–6 分钟）
知识点：目标 → 解释 → 关键点/步骤 → 示例 → 常见坑 → 面试表达
章节：参考来源 + 5/8 道练习 + 代码题
```

## 交互

- `/learn/[track]/[level]`：章节目录，显示“知识点 1/3”及顺序，不再出现“微课”字样。
- `/learn/.../[atom]`：顶部“知识点精讲”，正文按目标、讲解、关键点、示例、坑、面试表达顺序；底部显示下一知识点/章节练习；侧栏显示章节顺序与参考来源。
- 参考来源外链使用 `target="_blank" rel="noreferrer"`，标注“官方文档/公开课程”；不把外部链接当作完成条件。

## 数据

- `atom.objective?`：本节目标，一句话。
- `atom.explanation?`：150–300 字讲解（可选；旧内容可先使用关键点作为讲解）。
- `atom.teachingSteps?`：2–5 个步骤，“先…再…最后…”。
- `chapter.references[]`：`{ title, url, publisher, note? }`。
- 所有外部链接必须通过人工核验并记入 `docs/SOURCES.md`；UI 显示核验日期。

## 验收

- [x] 每个知识点都能按固定教学结构阅读；键盘/移动端可用。
- [x] 每个章节显示官方参考来源，链接可打开。
- [x] 无“视频”暗示或假视频占位。
- [x] 内容契约校验覆盖 tutorial 字段与来源格式。
