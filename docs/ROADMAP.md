# 职跃 OfferPath · 后续方向规划

> 本文只做方向规划，不代表任何新方向已实现。当前代码与内容仍以移动端、全栈两个方向为准。

## 1. 当前阶段边界

- 本阶段只交付两个方向：**移动端开发**（Android/Kotlin 为主线，含 Compose、协程、性能、跨端判断）与**全栈开发**（HTML/CSS、JS/TS、React、Node、SQL、安全与系统设计）。
- 两个方向共用一套内容契约、等级、技能词典、练习/错题/计划/面试与记录；不为单一方向写死页面。
- 当前阶段完成后**停止新增方向功能**：不并行开新方向、不提前占导航、不建空壳课程。后续方向按下文优先级逐个立 REQ。
- 现状：功能代码已铺开但处于 in-progress；工作区仅见 `fullstack.json`，移动端与面试题库文件待补齐；GitHub 未授权/未推送。完成度以各 REQ 验收为准。

## 2. 规划原则

1. **先内容后页面**：先完成 JSON 课程/题库、技能词典、等级差异与验收题，再写页面；内容未过校验不进入导航。
2. **每新增方向一份 REQ**：写清目标岗位、非目标、9 章大纲、技能 ID、题目/代码题形态、评测方式、页面复用点与验收；不把多个方向塞进一个需求。
3. **不提前建空壳**：不建「敬请期待」课程页、假题库、假进度、假 AI；路线图可以展示「规划中」，但不可点击进入空功能。
4. **复用 9 章骨架**：每方向 3 级 × 3 章 = 9 章 / 27 微课 / 45 单选题 / 9 代码题；每级 15 道面试题；章节 ID、技能 ID、题目 ID 全局唯一。
5. **先定评测再写题**：代码题能否执行、数据库/网络题如何判、面试评分用哪些要点，必须在内容生产前决定；不能执行的题只能做「参考实现 + 自评」，不得伪装自动判分。
6. **单方向试点**：新方向先以 1 个等级或 1 条完整 9 章路线内测，通过内容校验、真实浏览器走查与至少 5 名目标用户试用，再扩等级/导航。

## 3. 方向规划

### 3.1 后端开发（Backend）

- **目标用户/岗位**：准备后端实习/初级、初级升中级，或全栈转后端的开发者；岗位关键词为服务端开发、API、业务系统。
- **与现有内容关系**：直接复用全栈的 `node-runtime`、`http-api`、`sql-database`、`auth-security`、`performance-caching`、`system-design`；新增服务端专属的并发、消息、可观测性与数据一致性章节。
- **课程规模**：复用 9 章骨架；建议 Node.js/TypeScript 为主线（与全栈共享代码题），Java/Go 作为后续子方向另立 REQ。27 微课、45 题、9 道代码题（纯函数/算法型可执行，HTTP/DB 型用场景题 + 参考实现）、15 道面试题。
- **依赖**：内容生产（服务端场景与故障案例）；技能词典新增消息队列、缓存一致性、可观测性等 ID；执行方式需决定是否引入服务端沙箱/容器，不能把网络与数据库操作放进现有浏览器沙箱。
- **优先级与阶段**：P1，当前阶段完成后的第一优先；与全栈复用最高，先做 Node.js 主线试点。

### 3.2 前端开发（Frontend）

- **目标用户/岗位**：前端实习/初级、偏浏览器与 React 的求职者；岗位关键词为 Web 前端、React、可视化/中后台。
- **与现有内容关系**：复用全栈的 `html-css`、`javascript-core`、`typescript`、`react-fundamentals`、`state-data-flow`、`performance-caching`；新增浏览器运行时、工程化、可访问性、设计系统、SSR/渲染与前端系统设计。
- **课程规模**：9 章 / 27 微课 / 45 题 / 9 代码题；代码题以 DOM/事件/状态/性能小实验为主；15 道面试题。
- **依赖**：内容生产；技能词典拆出浏览器、构建、可访问性等 ID；执行沙箱需支持 DOM/浏览器预览（当前仅同步纯函数 Worker，不满足）；需要视觉回归与浏览器验收基线。
- **优先级与阶段**：P1，与后端同批评估；因与全栈重叠大，可先复用全栈前端 3 章做前端专项路线，再补 6 章。

### 3.3 iOS 开发（iOS）

- **目标用户/岗位**：iOS 实习/初级、移动端转 iOS 的开发者；岗位关键词为 Swift、UIKit/SwiftUI、iOS 工程化。
- **与现有内容关系**：只复用移动端的生命周期、架构、性能与发布方法论，语言与生态（Swift/Xcode/SwiftUI）是全新内容；不能把 Kotlin 章节改标题当作 iOS 课程。
- **课程规模**：9 章 / 27 微课 / 45 题 / 9 代码题；初期代码题只提供参考实现 + rubric 自评（无浏览器内 Swift 执行），15 道面试题。
- **依赖**：Swift/iOS 内容作者与审校；独立技能词典；若要自动判题需 macOS/Xcode 执行环境，成本高，默认不做；截图/示例工程需要真实构建验证。
- **优先级与阶段**：P3，排在 Web 与后端之后；先做 1 个等级 3 章试点，验证需求后再扩 9 章。

### 3.4 数据开发 / 数据分析（Data）

- **目标用户/岗位**：数据分析、数据开发、BI/数仓方向的入门与转岗者；岗位关键词为 SQL、Python、数据建模、指标与 ETL。
- **与现有内容关系**：复用全栈 `sql-database` 的索引、JOIN、事务基础；新增 Python、数据清洗、指标口径、数仓分层、批流与数据质量。
- **课程规模**：9 章 / 27 微课 / 45 题 / 9 代码题；代码题以 SQL 查询与 Python 数据变换为主；15 道面试题。
- **依赖**：内容生产（真实业务口径与数据集）；技能词典；评测需 SQL 沙箱（SQLite/Postgres）与 Python 执行环境，现有浏览器沙箱不足；需要样例数据集与可复现答案。
- **优先级与阶段**：P3；先做 SQL 专项 3 章，验证「可执行 SQL 判题」后再决定是否扩为完整方向。

### 3.5 测试开发（Testing）

- **目标用户/岗位**：测试开发、QA、研发提效方向；岗位关键词为自动化测试、接口测试、单测、质量门禁。
- **与现有内容关系**：复用全栈 `testing`、`javascript-core`、`http-api`、`deployment-devops`；新增测试设计、Mock、契约测试、端到端、性能与质量度量。
- **课程规模**：9 章 / 27 微课 / 45 题 / 9 代码题；代码题可执行「写测试/找 bug/断言」型 JS 题；15 道面试题。
- **依赖**：内容生产（缺陷案例与测试策略）；技能词典；执行沙箱需支持测试框架与多文件运行，当前单函数 Worker 不足；需要稳定的 fixture。
- **优先级与阶段**：P2；与前端/后端共用 JS/TS 执行能力，可在二者之后作为横向专项。

### 3.6 DevOps / 安全（DevOps & Security）

- **目标用户/岗位**：DevOps、SRE、应用安全入门者；岗位关键词为 CI/CD、容器、云资源、认证授权、安全审计。
- **与现有内容关系**：复用全栈 `auth-security`、`deployment-devops`、`performance-caching`、`system-design`；新增 Linux/网络、容器编排、IaC、监控告警、供应链与安全运营。
- **课程规模**：9 章 / 27 微课 / 45 题 / 9 代码题；大量题以配置/故障排查/方案设计呈现，代码题只保留可安全执行的小型脚本；15 道面试题。
- **依赖**：内容生产（真实事故与合规边界）；技能词典；执行沙箱涉及容器/云资源，风险与成本高，MVP 阶段默认「场景题 + 参考实现 + 自评」，不提供真实集群操作。
- **优先级与阶段**：P2/P3；先做安全基础（认证、越权、注入）横向专项，再评估 DevOps 完整方向。

### 3.7 AI 应用开发（AI Application）

- **目标用户/岗位**：想在业务中落地 LLM 的后端/全栈开发者；岗位关键词为 RAG、Agent、评测、提示工程、成本与安全。
- **与现有内容关系**：复用全栈的 API、数据库、缓存、安全与系统设计；新增 LLM 基础、检索、工具调用、评测、幻觉与注入防护、成本/延迟、上线与回滚。
- **课程规模**：9 章 / 27 微课 / 45 题 / 9 代码题；代码题以纯函数型检索/分块/评测指标为主，真实模型调用只做可选实验；15 道面试题。
- **依赖**：必须先有 LLM 适配需求：供应商与密钥管理、费用上限、超时/降级、数据脱敏、离线评测集；规则引擎保留为降级路径。没有密钥与验收基线前不写「AI 课程已上线」。
- **优先级与阶段**：P4，最后做；先做「AI 应用概念 + 评测」3 章试点，禁止在现有产品里把规则引擎包装成大模型。

## 4. 推荐阶段

| 阶段 | 范围 | 进入条件 |
| --- | --- | --- |
| A（当前） | 移动端 + 全栈 | 两端 9/27/45/9 内容、QA、GitHub 发布完成 |
| B | 后端、前端 | 阶段 A 退出门槛满足；单方向 9 章内容通过校验 |
| C | 测试、DevOps/安全、数据 | B 的方向有真实使用数据；执行沙箱方案定稿 |
| D | iOS、AI 应用 | 独立预算/环境/合规评估；各自单独 REQ 与试点 |

## 5. 方向准入与退出

- 准入：一份 REQ；9 章大纲与技能 ID；27/45/9 内容；15 道面试题；评测方式；页面复用清单；至少 1 个等级可完整走通。
- 退出/暂停：内容校验不过、题目无法评测、无目标用户验证、维护成本超过收益时暂停，不保留空导航或假课程。
- 每个方向完成后更新 `docs/requirements/README.md` 与本文状态；未完成前只写「规划中」。

## 6. 明确不做

- 不把其他方向写成已实现；不在导航放空壳；不复制两套进度；不为新方向重写页面骨架。
- 不在没有密钥、预算与评测集时接真实 LLM；不把 Kotlin/Swift 参考实现宣称为自动判题。
- 不在当前阶段做支付、社区、排行榜、简历生成导出、多租户或公网高可用部署。
